<objective>
Make the map camera stationary: the party sprite/ring moves across a fixed map, and the canvas only moves when (a) the player drags it, (b) the party is about to walk off the visible edge (scroll it back inside a margin, never to centre), or (c) an explicit centring event fires — the CENTRE chip, a new level (stairs / floorChanged), a teleport, a new run / boot first paint.

Purpose: today `positionCanvas()` pins the party at the viewport centre + a CSS-px `pan` offset, and `stepWith()` calls `window.mzCenterMap()` after EVERY `moved` event (plus tab return, overlay dismiss, Settings close and pinch-end), so the whole map slides one cell under the player on every step. The user wants the tabletop feel — the map holds still, the piece moves.

Output: a camera anchored to a grid point (`cam`, cell units) instead of the party; a pure `keepInViewAxis` rule in controls.js with behaviour tests; every former auto-recentre site retargeted to keep-in-view except the four allowed centring triggers; the Phase 33/35 source-assertion tests re-pinned to the new contract; a manual browser sanity checklist.

Scope rule (project CLAUDE.md): UI-only. No `S`/`act()`/engine changes, no save-format changes, nothing under engine/, content/ or test/parity/ is touched.
</objective>
