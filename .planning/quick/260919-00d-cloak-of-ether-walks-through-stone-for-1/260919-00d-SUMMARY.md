# Quick Task 260919-00d: Cloak of Ether Walks Through Stone for 10 Squares — Summary

**A live Cloak of Ether now lets the party step onto any in-bounds square — wall or corridor — for 10 squares, with a real death rule (`die("entombed")`) if the window closes while they're inside rock; tap-to-move routes through the stone, the chip warns in voice, and zero parity fixtures moved.**

## The ruling, verbatim (user, 2026-09-19)

> "The Cloak of Ether should literally let you traverse through the stone walls. It makes it so you are not limited to the paths and travel on any squares. Limit it to 10 squares of movement. If your movement ends when you are in a wall, you die."

Correction (same day): "there is no d-pad, we are fully tap to move now." — tap-to-move had to route through solid rock while the effect is live; there is no other movement affordance to consider.

This task is a delta on top of both quick 260918-w4n's (use-activated-only items) and quick 260918-wy1's (two jewelry slots) end states, both of which had already landed on master (commits `6e3c672`, `c49dd34`/`455c531`) before this task started, per the plan's hard precondition check.

## The numbers

- **Effect window:** 20 -> 10 squares (`act.effect` in `content/treasure-tables.js`)
- **Cooldown:** stays 80 (`act.cd` falls back to the row's own `every: 80`, unchanged — the user's own instruction: "cooldown stays 80 unless canon text says otherwise")
- **Once-a-day check:** 10 + 80 = 90 <= 100 ✓
- **Parity:** the row's exported shape (`n`/`eff`/`use`/`every`/`txt`) is byte-identical — `act` is stripped by `dropAuthored` before export, so the frozen economy fixture's DECLARED Cloak of Ether object (seed 3, Thief) never moves. `txt` ("once every 100 squares") is now slightly generous (usable every 90) but stays true and unedited.

## The engine rule (by function name)

- **`engine/movement.js#move`** — the first guard's wall test is now gated on `!itemEffectActive(state.c, "ether")`: a wall destination (border ring included) is refused only when no ether effect is live. Zero rng draws either way — every parity fixture (no `timers` key, no `useItem` call) takes the byte-identical refusal.
- **`engine/movement.js#resolveEtherEnd(state, rng, events, now)`** — the ONE home of the entombment rule. A no-op unless the party's current cell is solid rock (`inStone`); otherwise pushes `entombed` and calls `die(state, "entombed", null, rng, events, now)` — the same terminator starve/fall/gorge already use. Called today from exactly one site: `move`'s per-step `c.timers` tick block, the instant an `ether`-kind transition leaves its "effect" phase (kind-keyed via `ACTIVATION_OF`, never name-keyed).
- **Dispatch gate** — `move`'s feature dispatch gains an explicit `if (cell.wall) return events;` (genFloor never scatters a feature onto a wall cell anyway; the rule is now stated, not merely implied).
- **`newDay`** — the wandering-monster fight is skipped while `inStone(state)` is true; the eight per-hour d20 draws still happen in the exact same order (the rng cursor is unchanged — pinned by replaying the same seed both in the open and in stone and comparing `rng.getState()` after eight draws).
- **`engine/derived.js#inStone(state)`** — the one "is the party in rock" pure read every consumer (move, newDay, resolveEtherEnd, the shell bridge) shares, mirroring `inDark`'s own pattern.

## The death path

`die(state, "entombed", ...)` — new `CAUSE_TEXT.entombed`: "became a permanent architectural feature"; new four-line `EPITAPHS.entombed` bank, headline first: "Became a permanent architectural feature.", "The cloak wore off. The wall did not.", "Walked through walls for a living. Retired inside one, on floor {floor}.", "{name} is now load-bearing. The dungeon thanks {name} for the support." Event order on a fatal tick: `itemEffectFaded` (from `narrateTimerTransitions`) -> `entombed` -> `died`.

## Tap-to-move decision

The shell has no multi-step route builder — every tap is ONE adjacent step toward the tapped cell (`src/browser/tapStep.js#resolveStep`). So "route through rock" is entirely the `isOpen` predicate: while ethereal, `isOpen` accepts any in-bounds cell (`mazeworld.html#tapStep`, driven by the new `window.__mzEther.itemEffectActive(S.c, "ether")` bridge read). A tap on a wall cell — adjacent or ten squares away — resolves one step toward it; the player taps again for the next square, watching the chip count down. Because there is no route preview and no multi-square walk in one dispatch, there is nothing to cap: "a route that would outlast the remaining squares" cannot exist structurally.

Hold-inspect (`inspectCell`) gained a third `opts` argument: while ethereal, a seen wall shows `RAIL_COPY.rockEther` ("Passable, for the moment. Do not be inside it when the moment ends.", tone "odd", `RAIL_HOLD.mark`) instead of the plain SOLID ROCK card. An unseen wall stays UNWALKED either way — fog never reveals rock, ethereal or not.

## Chip / toast / narration copy

- **Ethereal chip:** the existing `N sq` countdown detail is unchanged; `paintConditions()` now turns the chip's tone `warn` while `window.__mzEther.inStone(S)` is true (only when the ether chip is showing AND the party is currently in rock).
- **Activation toast + Oracle line:** `itemEffectStarted.ether` now reads "N squares of walking through stone. Be in a corridor when it ends — the stone will not make room." (both `src/browser/toasts.js` and `eventNarration.js`).
- **Entombed toast:** "The cloak gives out. The stone does not." (hurt tone, `PRIORITY.you`) — an outcome, never ORACLE_ONLY (mirrors `fellClimbing`/`fellInGorge`). Same line as the Oracle's hurt-span narration.
- **`CONDITION_EXPLAIN.ether`:** "Walls are a suggestion for the count shown. When it reaches zero, be standing in a corridor. The rock will not be."

## Accepted edge behaviours (stated, not new code)

- **Being-trapped phobia in rock:** a phobic hero stepping into solid rock (0 open neighbours) takes the existing deterministic `trappedPanic` hit and arms Afraid, exactly like any other dead-end entry — no new field, thematically apt.
- **Camping in rock:** not refused — the ether record is squares-cadence (a camp doesn't advance it) and the in-stone wandering-monster skip covers the camped `newDay` too. Solid rock is the safest bed in the dungeon for as long as the cloak holds.
- **One-way doors:** unaffected either way — ether does not override a door, and a wall cell has `feat: null` anyway so the approach check never fires there.
- **The bot:** `tools/lib/tuning-bot.mjs#canStep` refuses any wall destination unconditionally (it reads only the floor, never `c.timers`) and no bot policy ever activates an ether-kind item — the bot structurally can never be entombed. Pinned directly.
- **Old saves:** tolerant-load only — `engine/saveState.js#foldLegacyCounters` already rehydrates a pre-Phase-39 `c.ether` counter into an `item:Cloak of Ether` effect record; that record (whatever `left` it carries) simply obeys the new rule going forward. No gating, no dual path.
