<objective>
Turn the LINEAGE leaderboard from "one row per race-and-class combination" into "top 10 runs for one lineage": a race selector and a sub-class selector at the top of the board, defaulting to the active hero's race + sub-class, with the list below showing the ten deepest runs of exactly that lineage (locally from the device's own runs; signed in, filtered from the cached 25-entry DEEPEST sample).

Purpose: user device feedback 2026-09-24 (milestone v2.0) — "lineage doesn't quite work unless you have a selector to choose the lineage. We should be able to choose race and sub class and then see top 10 for that selection. It should default to whatever your current race selection on your active character are."

Output: records support for a correct per-lineage top ten over time (engine/records.js), the new LINEAGE view model (boardsView.js) and copy (content/boards.js), the picker in the panel (boardsPanel.js) and its shell wiring + CSS (mazeworld.html), all with tests; a SUMMARY.

Sub-class ruling (verified in code, recorded here per the orchestrator's instruction): in this codebase `cls` is the base class (Magic User / Fighter / Thief — content/classes.js CLASSES keys) and `sub` is the sub-class (Wizard, Knight, Pickpocket, … — CLASSES[cls].subs). The old lineageKey grouped on race + cls, but every row displays "RACE SUB · LVL n" and the user asked for race + sub-class. Ruling: the lineage becomes race + sub; lineageKey changes to race + sub; the selector offers the 24 sub-classes. Greenfield: the old one-row-per-lineage view, its lineage {count, best} aggregate map and its copy are removed, with no dual path.

Records ruling (declared per the orchestrator's permission to extend engine/records.js): the existing stores cannot yield a correct per-lineage top ten over time — the graveyard caps at 60 and prune deletes any run off every ranked board, so a lineage's 3rd-best run from months ago is gone. Instead of adding a stored list, prune itself keeps each lineage's top BOARD_TOP_N runs (grouped by the new lineageKey, ranked by lineageRuns). By induction every lineage's true top ten from the day this ships is always held in ddr.bests.v1's runs map, the view derives the list from those runs, and no new field is written. The Phase 65 lineage {count, best} map (which only served the retired view and the LINEAGE new-best) is retired: sanitizeBests ignores it on load and it is simply absent from the next save; the record stays v 1 since nothing else reads it. The LINEAGE new-best keeps 65 D-14's rule exactly (only when strictly beating an existing best of the same lineage, never first-of-lineage, never on a tie), now computed from held runs. Storage stays bounded: at most 10 runs per distinct lineage (6 races × 24 sub-classes = 144) on top of the five boards. Pure, deterministic, no GameState change, test/parity untouched, no fixture moves.
</objective>
