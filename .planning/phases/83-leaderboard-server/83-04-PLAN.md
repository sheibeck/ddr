REST response shapes the fake must produce and the client must read:
- runQuery: 200 with a JSON array; each hit is {document: {name, fields, createTime, updateTime}, readTime}; no hits is [{readTime}].
- runAggregationQuery: 200 with [{result: {aggregateFields: {count: {integerValue: "N"}}}, readTime}].
- commit: 200 with {writeResults: [...], commitTime}.
- document get: 200 {name, fields, createTime, updateTime} or 404 {error: {code: 404, status: "NOT_FOUND"}}.
- Errors: {error: {code, message, status}} (restError also accepts the array form). A rules denial is 403 status PERMISSION_DENIED; a bad or expired token is 401 UNAUTHENTICATED; a failed precondition is 400 FAILED_PRECONDITION; an already-existing doc may surface as 400 FAILED_PRECONDITION, 403 PERMISSION_DENIED or 409 ALREADY_EXISTS (unverified live until 83-08, hence the existsResponse option).
Fake error bodies use the status id as the message (for example message "PERMISSION_DENIED") so no English sentence enters src/browser.
