**Why the frame stack is phase-shifted opacity, not a background-image swap.** The 2026-09-17 UAT PERF fix (see the `.mw-party-pulse` CSS comment in mazeworld.html) established that the map's animated DOM chrome animates only composited properties: a non-composited animation re-rasterised the map layer every frame on the Pixel 7. Plan 59-03 therefore stacks the four idle frames as four images and runs ONE opacity keyframe on each, phase-shifted by a negative delay so exactly one is opaque at a time. `idleFrameDelaysMs()` is the single source of those delays. Under the blanket reduced-motion CSS rule every animation is removed, so each frame falls back to its base style, and only frame 1's base style is opaque: that is D-05's "idle freezes on frame 1" with no JS at all.

**Why `displayed(real)` self-heals.** Only a genuine step starts a glide (59-04 wires it from `stepWith`'s `moved` event). A teleport, a floor change, a new run or a load moves the party without one. If a glide happened to be in flight at that moment, its target is now a stale square. Checking `target === real` on every read ends such a glide on the next position call, with no extra hook in `centerMap` or any other pinned function.
