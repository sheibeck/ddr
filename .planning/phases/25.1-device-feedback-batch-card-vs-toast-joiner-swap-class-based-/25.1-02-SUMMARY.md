# Phase 25.1 Plan 02: Joiner Swap + Camp Refusal Numbers Summary

**Accepting a second Joiner with a full roster now swaps the incumbent out with a deterministic, escaped snark line (`joinerLeft` before `joinerJoined`) and the offer card names who would walk, while a single exported `nightlyEats(state)` helper now drives both the automatic new day and the camp gate — the refusal states the numbers, the camp button visibly (but non-disruptively) reflects the same math, and solo runs stay byte-identical.**

## Performance

- **Duration:** ~50 min
- **Tasks:** 3
- **Files modified:** 8 modified, 1 new (test)

## Accomplishments

- `engine/state.js`: new `swapPartyMember(state, member)` export — under `PARTY_CAP` it appends with `left: null`; at cap it splices index 0 out and returns it as `left`. Zero rng, plain data mutation; `addPartyMember`'s existing refuse-when-full contract for every other caller is untouched.
- `engine/encounters.js`: `resolveJoiner`'s accept branch now calls `swapPartyMember` unconditionally when a candidate exists. When a member is swapped out, `joinerLeft { name, sub, replacedBy }` is pushed **before** `joinerJoined`. Declining (or no candidate) still emits only `joinerDeclined`. Still zero rng.
- `content/flavor.js`: `JOINER_EXIT_LINES` — five family-friendly snark templates (`{name}`/`{new}` placeholders).
- `src/browser/eventNarration.js`: `joinerLeft` entry — picks a line by `(name.length + replacedBy.length) % 5` (no rng), escapes both interpolated names via a local `escapeHtml` helper so a name containing `<` never becomes a live tag; `campFailed` rewritten to render `"You eat N a night (Member eats M more). You have H. Find rations first."`, degrading to `"?"` for a bare payload.
- `src/browser/toasts.js`: `joinerLeft` added to `FEATURE_EVENTS` and given a `TOAST_FOR` builder (fallback/coverage text — the resolveJoiner action's narrative ctx from 25.1-01 shows the Oracle sentence instead on a real run); `campFailed`'s toast now renders the numbers when present, otherwise the original generic block text.
- `engine/movement.js`: new exported `nightlyEats(state)` — hero's `RACES[race].eats||1` plus every live party member's `RACES[m.race]?.eats||1`. `newDay` now reads `eats` from it (member loop keeps summing `upkeep()` into `cost` only). `makeCamp` computes `need`/`have` via the same helper and, before any mutation or rng draw, refuses with `{ type: "campFailed", reason: "noRations", need, have, ...(members.length ? { members } : {}) }` — the `members` key is present only when a party exists, so the solo shape is exactly the pre-plan `{ type, reason }` plus the new `need`/`have` (additive, no new field on a solo run beyond the two numbers).
- `mazeworld.html`: module script imports `nightlyEats` (engine/movement.js) and `PARTY_CAP` (engine/state.js), bridged read-only as `window.__mzNightlyEats` / `window.__mzPartyCap`. The pendingJoiner offer branch computes `walker = S.party.length >= cap ? S.party[0] : null` and builds the head via `document.createElement("p")` + `textContent` (`"Take {j.name} along? {walker.name} walks."` when full, the original text otherwise) instead of the old template-literal `innerHTML +=`. `paint()` sets `#btn-camp`'s `data-short` attribute and `aria-label` from `window.__mzNightlyEats(S)` vs `c.rations`; new CSS (`#btn-camp[data-short="1"]{opacity:.55;border-style:dashed}`) dims it. The button is never `.disabled` — tapping it while short still dispatches `camp` and lets the engine's `campFailed` toast state the numbers.
- New/extended tests: `test/unit/joiner-acquisition.test.js` (rewrote the old cap-refusal test into a swap test, added decline/empty-roster/rng-free/swapPartyMember cases), `test/unit/party-model.test.js` (+1 swap test), `test/unit/movement.test.js` (+9 nightlyEats/makeCamp/newDay/narration-toast tests), `test/unit/narrativeToasts.test.js` (+3 joinerLeft tests), `test/voice/safety-scan.test.js` (JOINER_EXIT_LINES added to the scanned corpus), `test/unit/shell-party-camp.test.js` (new, 4 source-assertion tests for the bridges/offer-head/camp-button).
- Final suite: `npm test` 1377/1377 (1357 baseline + 20 new); `node --test "test/parity/**/*.test.js"` 33/33 with a clean `test/parity` tree and `prototype-master.js.txt` untouched; `npm run build:www` exits 0; `git status --porcelain engine/combat.js engine/derived.js` is empty — neither file was touched.

## Device checklist (non-blocking, for the orchestrator's phone-push offer)

1. Accept a Joiner with an empty roster → they join, no exit toast/line.
2. Accept a second Joiner while the roster is full → the offer card reads "Take X along? Y walks."; on accept, a snark exit toast/Oracle line for Y appears before the "X falls in beside you" line; the roster still shows exactly one member.
3. Decline a Joiner offer while the roster is full → the original member stays, only the "You wave them off" line/toast appears.
4. With a full ration bag, make camp normally → succeeds as before.
5. Let rations run low (e.g. a Troll with 1 ration) and tap Make Camp → the button looks visibly dimmed/dashed beforehand, and tapping it surfaces "You eat 2 a night. You have 1. Find rations first." as a toast and in the Oracle.
6. Recruit a party member, then let rations run low relative to the combined appetite → the camp button dims and the refusal names the member ("...Bram eats 1 more...").
7. The automatic new day (every 100 squares) still eats/starves exactly as before, party or no party.
