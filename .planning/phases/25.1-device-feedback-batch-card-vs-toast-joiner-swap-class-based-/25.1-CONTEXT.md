## Implementation Decisions (verbatim from the user-approved brief)

## Decisions (user-accepted)
1. The dismissible beat card ("Move on") is reserved for DECISIONS and BIG UPDATES only:
   encounter start (the Fight! gate — already handled by awaitingFight), a Joiner offer (pendingJoiner), a find to keep/leave (pendingFind),
   death (preDeath card), a NEW FLOOR (floorChanged), a LEVEL-UP (leveled), and the end-of-fight report (noteCombat).
2. Everything else is TOAST-ONLY on the move path: traps (sprung/dodged/disarmed), climb/leap/fall results, chests, gold/rations/food found,
   darkness, afflictions cured/lingering, camp rest results, TELEPORT (the teleport-square hop, including the Illusionist's chosen destination — user addition 2026-09-15), etc. For these, the toast TEXT is the Oracle narration line with roll detail
   stripped (plain text, no HTML) — the sarcastic sentence, not the terse label — so the "narrative fun" moves from the card into the toast.
   The Oracle log keeps every line as before (unchanged).
3. Toasts linger: base lifetime ~2x the old (old: min(4200, 1500 + 45*len)); new: min(9000, 3000 + 60*len) PLUS +1200 ms per toast already
   visible when it is raised (so a stack of four does not vanish together); tap/click a toast to dismiss it early; reduced-motion respected;
   host cap stays 4; no layout shift (fixed host).

## Where
- mazeworld.html: the engineMove post-dispatch block (~L5818–5875) that builds `state.beats` from `html` when no combat/store/joiner/find —
  gate it on a BEAT_CARD_EVENTS whitelist (floorChanged, leveled) instead of "any html"; when the whitelist doesn't match, raise toasts from
  the narration lines (stripped) for the toast-only events instead. Keep preDeath/awaitingFight/joiner/find behavior exactly as is.
- mazeworld.html `window.mzToast` (~L2655): lifetime formula, stacking bonus, tap-to-dismiss.
- src/browser/toasts.js: if needed, a helper `narrativeToastText(html)` (strip HTML tags + roll detail) so the shell doesn't own string munging;
  keep the module pure. Tests: test/unit/shell-toast-wiring.test.js (lifetime constants, whitelist presence, tap handler), toasts tests for the helper.
- No engine changes. `npm test` (1330) green; `npm run build:www` green.

## Acceptance (device)
- Walk onto a trap: a toast with the Oracle's sentence appears; NO Move on card.
- Step on a teleport square: a toast ("…and you are somewhere else"), the map recenters, NO card.
- Descend a floor: the card appears (new floor).
- Level up: the card appears.
- Four toasts in a row are readable one by one; tapping one removes it.

## Joiners fight by class (engine combat)

    hero's current target using the thrown/status resolution (reuse magic.js pieces or a slim ally-cast path); otherwise staff-swing like a Fighter

  - All new rng draws are gated on state.party?.length (existing gate) → parity byte-identical (fixtures have no party).
  - Events: allyStruck/allyMissed extended additively (weapon, crit, backstab), new allyCast/allySpellHit/allySpellMissed narrated + toasted

## Camp refusal says why (user decision 2026-09-15: keep refusing, but show the numbers)
- Bug: makeCamp (engine/movement.js ~L526) refuses with `campFailed { reason: "noRations" }` whenever `c.rations < R.eats` (a Troll eats 2, so
  1 ration reads as "no rations"); the narration/toast say only "Not enough food to make camp." Also makeCamp counts ONLY the hero's appetite while
  newDay counts the party's too — so a hero with a member can pass the camp gate and still go hungry that night.
- Fix (engine, zero rng): compute `need` the same way newDay does (hero eats + every live member's eats — extract ONE helper `nightlyEats(state)`
  used by both), refuse when `c.rations < need`, and make the event carry the numbers: `campFailed { reason: "noRations", need, have }`.
  Narration + toast: "You eat 2 a night (Bram eats 1 more). You have 1. Find rations first." — voice, family-friendly. The camp button's disabled
  state (shell) uses the same helper via a read-only export so the button and the engine never disagree.
- The automatic new day (every 100 squares) is UNCHANGED: it still rolls over, eating when it can and going hungry (−upkeep hp, no heal) when it
  can't — canon starvation path. Parity: the fixtures' camp actions must stay byte-identical — the refusal condition is only WIDENED for
  characters with a party (no fixture has one); for a solo hero `need === R.eats` exactly as before, and the added event fields are additive.
- Tests: Troll with 1 ration → campFailed need 2 have 1; Human + member each eating 1 with 1 ration → campFailed need 2 have 1; solo Human with
  1 ration → camps; event payload asserted; existing movement/camp tests unchanged.

## Oracle opens at the most recent line (user, 2026-09-15)
- The Oracle log prepends new lines at the TOP (`logEl.insertBefore(p, logEl.firstChild)`, mazeworld.html ~L2642), so "most recent" is the top.
  Whenever the Oracle panel is opened/shown, scroll the log to the most recent text (scrollTop = 0 for the prepend layout) — and while the user
  is scrolled away from the newest line, show a small "↑ newer" / "scrolled" indicator pill that taps back to the top. The indicator hides when at
  the top. If the layout is changed to fill the screen (item above), keep this behaviour consistent with whichever end holds the newest line.
- Shell/CSS only; a source-assertion test in shell-toast-wiring (or a sibling shell test) checks the open-handler scroll call and the indicator
  element/handler exist.
