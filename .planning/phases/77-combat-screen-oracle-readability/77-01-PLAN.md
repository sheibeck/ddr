## Flagged assumptions (surfaced, not silently decided)

- **CMBUI-08 edge probe: unclassified, reviewed manually.** Resolved as: the sort key is the EFFECTIVE level (`spellLevelFor(c.sub, sp)`, the same level canCast gates on), then the upper-cased label compared by code unit (names are ASCII and unique in SPELLS, pinned, so no two rows compare equal; SPELLS index is the final tie-break for safety). The LVL label switches from the base `sp.lvl` to that effective level so the list never reads out of order (only the Illusionist's Phantom Host differs today: base 3, effective 1). Out-of-charges rows sort in place with the rest; locked spells stay hidden.
- **Likely root cause of the clipping (CMBUI-07), to be confirmed by the executor:** `.cb-sub-list` is a column flex container capped at 206px with `overflow:auto`, and `.cb-row` sets an explicit `min-height:48px`, which replaces the flex item's content-based minimum. When a submenu's rows add up to more than 206px, every row shrinks toward 48px and its description spills past the bottom border. Rows that do not shrink (plus a wrapping label) fix it; the list keeps its 206px scroll cap. If the measurement shows a different cause, fix that cause and record it.
- **The combat screen does not follow the S/M/L text-size setting today** (its CSS is fixed px, unlike the Gear and Hero surfaces). The fix is content-driven sizing, so it holds at any font size; scaling the combat screen with the setting is Phase 78's text-size work, not this plan's.
- **"Can't swap mid-fight" is true:** engine/items.js#equipItem refuses through `refuseGear`/`gearLockReason` during a fight. The reason text states that fact; nothing about equipping changes.
