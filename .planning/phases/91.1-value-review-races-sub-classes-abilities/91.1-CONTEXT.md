<domain>
## Phase Boundary

Every race, sub-class and ability has every system its text names, and earns its place. A value ledger in `docs/` covers every race (6), every sub-class (24) and every ability (skills, level-up abilities, active abilities), lists every system each text names and confirms it exists in the engine (or marks the gap), and flags everything weak, tiny, one-round or once-per-combat with a recommendation. The user rules on each flagged entry at ONE batched checkpoint mid-phase; then the approved changes are built, their text updated, each pinned by a test.

Requirements: VALUE-01, VALUE-02, VALUE-03, VALUE-04. No bot pass (Phase 92 measures these changes once).

</domain>

## Implementation Decisions

### The user's request (2026-09-29, verbatim)
"iterate over every sub-class and every race and every ability and once again make sure we've accounted for all systems in the text. Or update them as necessary. If a system seems like it provides little or no value to how the game works, surface these things so we can modify them, or add new systems. Also, check for very low bonuses, or effects that only last for a single round. We might want to re-visit once per combat skills again to see if any in there deserve more than once per combat."

### Flow (user ruling, roadmap)
- Findings first: `docs/VALUE-LEDGER.md` (one row per race, sub-class and ability: systems named → exists? / gap; value flags: little-or-no value, very low bonus, single-round effect, once-per-combat; recommendation: keep / buff / lengthen / rework / allow more uses / cut / new system). It builds on the closed audits (`docs/ITEM-AUDIT.md`, `docs/SPELL-AUDIT.md`, `docs/SKILL-AUDIT.md`, `docs/IDENTITY-AUDIT.md`) — it does not re-audit text-vs-engine; it judges value.
- Then ONE batched `checkpoint:decision`: every flagged entry as a numbered question with options and a recommended default, so the user can answer "accept recommended" or rule per item. Group questions so the batch is readable (by class/race; once-per-combat items together; single-round items together).
- Then build only what was approved: engine + text + a pinning test per change; moved fixtures measured, declared and regenerated alone.

### Known findings handed forward (must each get a ledger row and, if flagged, a question)
From docs/SPELL-AUDIT.md, docs/SKILL-AUDIT.md and docs/IDENTITY-AUDIT.md "Findings for other phases → Phase 91.1":
- The MU chart's bonuses on protection, healing, divination and illusion change no roll (rulebook p.18 says they add to damage, number affected, additional healing or squares); the Illusion bonus is 0 for both sub-classes that learn it, so the Q6 stretch gives Senseless and Duplicate Foe nothing (only Stop Time stretches).
- Bard songs cast at +0 school bonus (91-06/07 assumption; a Wizard gets +3 offense).
- A Joiner's Enchant Character staff blows do not read the +2 to hit (`memberToHit`).
- A Joiner's Ambidextrous applies to a plain strike only; a Joiner's Stealth dark ban applies to the Stealth crit only; a Joiner uses only its first round-1 opener and never reuses it after cooldown.
- A fixated Walking Dead's ability bolts use the plain target pick; a Joiner Bard's sung Turn Walking Dead fixates nothing; a Joiner Bard lacks the hero Bard's dim-witted-foes drawback.
- Weaken's to-hit cap is not applied to misdirected swings (Senseless, Duplicate Foe).
- A Joiner's sub-class specials are the hero's only (Barbarian second attack, Cat Burglar / Ninja free opener, Ninja and Cutthroat crits, Fridgian frenzy, Soldier crit exposure and camp heal, Apprentice backfire); Q7 covered only body protection.
- The Ninja's later crit and the Cutthroat's first crit ignore the dark no-crit ban.
- The Master of Arms' armour patch has no night limit; a Cloaker's vanish still lets a pursuing Spectre strike once; an Elf Illusionist's better strike die is cancelled at levels 1–2.
- The Joiner's Death never downs its caster (refuses at 26 HP or less).
- Dead code to clean (91-06 deferred-items.md): `C.inspired` readers (derived.js, conditionEffects.js, heroConditions.js, mazeworld.html labels) and the `beastsSoothed` "THEY STAND DOWN" check in mazeworld.html — remove as a non-balance cleanup (no question needed).
