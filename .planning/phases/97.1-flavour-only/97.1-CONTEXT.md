# Phase 97.1: Flavour Only - Context

**Gathered:** 2026-10-04
**Status:** Ready for planning
**Source:** user ruling during the v2.4 build gate. The user first said "we should NOT show the rules button", then chose "Remove rules entirely" over two other options: rules shown only when a setting is On, and the buttons hidden behind a setting.

<domain>
## Phase Boundary

Players see only the flavour lines. Phases 95 and 96 built a two-layer text model: flavour first, with the exact rules text behind a RULES toggle on every surface, plus a Settings switch "Always show the rules". This phase retires both.

After it:
- No RULES control is rendered anywhere.
- No rules body is rendered anywhere.
- No Always show the rules setting exists.

The exact rules data stays in code, because the v2.3 and Phase 95 truth-in-advertising guards read it. That data is RACE_NOTE, SUB_NOTE, CLASS_NOTE, the identity footers, the item notes, the spell, ability and skill `txt`/`txt2`, and CONDITION_EXPLAIN. It is simply shown nowhere.

This is shell, tests and docs work only. No engine change.

</domain>

<decisions>
## Implementation Decisions

### What players see
- Every surface that showed a flavour line plus a RULES toggle now shows the flavour line only. The surfaces are:
  - the roller reveal
  - the Hero tab dossier, trait line, abilities and special skills
  - the Gear tab and Gear sheet
  - the store and the sell list
  - the loot and find cards and the bag-full drop shelf
  - the Grimoire
  - combat SPELLS, ITEMS, ABILITIES and SING
  - chip taps (HUD strip, combat condition card, YOUR LOT, Company panel)
  - UP YOUR SLEEVE
  - the Final Sheet
- A surface or row with no flavour line keeps exactly today's text. This is the existing fallback; nothing goes blank.
- Numbers that already live outside the RULES layer stay as they are:
  - the Hero sheet stats
  - the combat menu's "Hit 16–20 · 8–17 dmg"
  - the Phase 94 state words (READY IN N and the rest)
  - the Oracle and rail narration
- The race and sub-class mechanical footers (`src/browser/identityFooter.js`) are no longer rendered. The module stays if guard tests import it.

### Settings
- The `alwaysRules` key leaves `SETTINGS_DEFAULTS` and `ALLOWED_VALUES`, and its row leaves the Settings sheet.
- An old saved settings blob that still carries `alwaysRules` loads without error and drops the key (greenfield, tolerant-load only, no legacy path).

### Code
- Retire the RULES machinery and delete what nothing needs. Expected:
  - `src/browser/rulesLayer.js`: RULES_COPY, setAlwaysRules/alwaysRules, rulesOpen/toggleRulesOpen/clearRulesOpen, layerText, mountRules, wrapRow
  - its bridge registry entries
  - its voice-corpus and flavor-review registrations
  - the RULES CSS
  - every call site in roller.js, heroTab.js, gearTab.js, gearSheet.js, storeScreen.js, finalSheet.js and mazeworld.html
- Where a helper still earns its keep (e.g. "flavour if present, else today's text"), keep or inline it. That is the planner's discretion.
- The rules data and every guard test that pins a rules number to the engine stay green, with no guard lost. Only tests that pinned the RULES UI change:
  - `rules-layer.test.js` is deleted with the module.
  - `flavor-sweep.test.js` S3/S4 become "no RULES control or rules body anywhere".
  - `rules-surfaces.test.js` is re-pinned or retired per surface.
- Every changed assertion carries a declared re-pin comment.
- Shell snapshots: regenerate only the fixtures whose markup loses RULES, each one declared. Candidates are fighter.abilities-states, fighter.hero-in-combat, mu-store.store, mu.gear, mu.hero, thief-store.store, thief.gear-sheet-bag, thief.gear-sheet-worn, thief.gear and thief.hero.

### Docs
- `docs/TEXT-LAYERS.md`: the rules layer becomes code-only (guards), not a player surface.
- `docs/patch-notes/2.4.0.md` (DRAFT): drop the RULES mentions and the "Always show the rules" bullet. The flavour bullets say the exact rules sit behind the scenes, in the voice.
- `docs/UAT-v2.4.md`: rows 5.1, 5.4 (the RULES-body item), 6.1–6.7 and 6.10 lose their RULES and Always parts, and a row checks that no RULES control is left.

### Claude's Discretion
- Plan split and wave shape. Expect 2–3 plans: the code retirement across modules plus mazeworld.html, then tests, snapshots and docs. Parallelism only where files don't overlap.
- Whether `layerText`-style fallbacks are kept as a tiny helper or inlined.

</decisions>
