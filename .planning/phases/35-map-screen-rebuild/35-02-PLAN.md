<objective>
Build the RAIL — the map screen's bottom card that replaces every out-of-combat toast and carries every decision — and retire the toast host, the Move-on cards and the overlay-style joiner/find cards in the same stroke (MAP-03, MAP-04, ruling 1/3/4, orchestrator decisions 2 and 6). `dispatchWithToasts`'s out-of-combat branch now folds through `rail.js` into `window.__mzRail` and `renderRail()` paints it; the joiner offer, the find offer and the CLIMB IT retry are rail cards with guarded action rows; `window.move` refuses every step while a decision or obstacle is pending (global lock, the card pulses); floor arrival / level-up become auto-clearing rail cards; out-of-combat death folds its pre-death lines into the existing `renderCombatOver(body, "dead", …)` (decision 5: re-pin, do not rebuild).

**Decisions recorded here:**
- **Decision 2 (movement lock: GLOBAL).** `railLocked()` = a pending joiner OR a pending find OR `window.__mzRail.pending` (a failed climb). `window.move` checks it after the settle clause and before any dispatch, for every entry path (D-pad this wave, tap-to-step and keys in Plan 04). A failed climb sets `window.__mzRail.pending = { kind: "climb", dir }` from the `fellClimbing` / `fellInGorge` event; CLIMB IT clears it and calls `window.move(dir)` again (the engine re-rolls synchronously inside `move`); a success (`climbedOver` / `leaptOver`) or death leaves it null. There is no pre-roll preview — the first tap toward a crevice IS the first attempt (RESEARCH Pitfall 3).
- **Decision 4 (no PICK THE LOCK).** The only chest decision is the existing `S.pendingFind` Take/Leave; `chestOpened` / `chestLocked` are plain auto-clearing cards.
- **Decision 5 (death).** Out-of-combat death keeps `renderCombatOver(body, "dead", …)`; the `preDeath` beat is no longer a "Move on" card — its lines are passed as `opts.lines` so THAT IS THAT shows the cause at once.
- **Decision 6 (toast retirement is total).** The toast host element (L1419), the toast CSS block (L775-806), the global toast builder + its doc comment (L2793-2827), the lifetime bridge (L6424-6427) and the module's `MAX_TOASTS` / `toastLifetime` / `CARD_EVENTS` imports all go; `src/browser/toasts.js` is not edited.
- **Claude's discretion:** the rail is placed OUTSIDE `#screen-maze` (a direct child of `#app` between `<main>` and `<nav>`) because ruling 1 routes EVERY out-of-combat event to the rail and Gear-tab Use/Equip and Hero-tab Cast dispatches (`window.mzUseItem` / `mzEquipItem` / `mzCastSpell`) happen off the map tab; the tab bar becomes a static flex child so nothing overlaps the rail; the rail hides only while `S.combat` / `S.dead` / `S.won` own the column (the combat screen has its own › log; the endings are over-panels). The pending-decision lock is `window.__mzRail.pending` (never on `S`). Rail bottom padding is 18px, not the mock's 30px — the mock's extra bottom space stood in for a home indicator the tab bar now owns.

Output: `mazeworld.html` (rail markup/CSS/render/lock/routing, retirements, static tab bar), `test/unit/shell-map-rail.test.js`, eight re-pinned suites.
