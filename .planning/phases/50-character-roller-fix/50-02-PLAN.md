  <action>
    Create `tools/roller-repro.mjs` (ESM, `#!/usr/bin/env node`, head comment naming Phase 50 / ROLL-01 / SC3 and the usage line).

    CLI: `node tools/roller-repro.mjs [--chrome <path>] [--port <n>] [--devtools-port <n>] [--scenario normal|double-tap|play-again|play-again-mid-reveal|all] [--json] [--keep-profiles]`. Defaults: port 8766 (boot-check uses 8765), devtools-port 9333, scenario all. Exit codes: 0 every row matched; 1 at least one mismatch (or an uncaught page exception during a scenario); 2 the browser could not be resolved or driven (print the reason on stderr — this is the fallback signal the SUMMARY must quote).

    Static server: serve the REPO ROOT (`path.resolve(import.meta.dirname, "..")`), `startStaticServer(root, port)` copied from shell-boot-check.mjs with its CONTENT_TYPES map (add `.json` → `application/json` and `.svg` → `image/svg+xml`); the page URL is `http://127.0.0.1:<port>/mazeworld.html`.

    Browser per scenario (a cold, save-less boot each time): temp profile `fs.mkdtempSync(path.join(os.tmpdir(), "mz-roller-"))`; spawn the resolved binary with `--headless=new --disable-gpu --no-first-run --no-default-browser-check --remote-debugging-port=<devtools-port> --remote-allow-origins=* --user-data-dir=<profile> --window-size=432,900 <url>`, `{ windowsHide: true, stdio: "ignore" }`. Poll `http://127.0.0.1:<devtools-port>/json/list` (global `fetch`) every 200 ms up to 15 s for an entry with `type === "page"` and `url` starting with the page URL; connect `new WebSocket(entry.webSocketDebuggerUrl)`. A tiny CDP client: an `id` counter, `send(method, params)` returning a promise resolved by the matching `id` message (reject on `error`), `Runtime.enable` once, and an `exceptions` array filled from `Runtime.exceptionThrown` events (any entry fails the scenario with its `exceptionDetails.text` in the notes). `evaluate(expression)` = `Runtime.evaluate` with `{ expression, awaitPromise: true, returnByValue: true }`, returning `result.result.value` and throwing on `result.exceptionDetails`. `waitFor(expression, timeoutMs, label)` polls `evaluate` every 100 ms until truthy, else throws `timeout waiting for <label>`. After the scenario: close the socket, kill the process tree (win32: `spawnSync("taskkill", ["/PID", String(child.pid), "/T", "/F"])`; else `child.kill()`), and `fs.rmSync(profile, { recursive: true, force: true })` unless `--keep-profiles`.

    Page-side expressions (build them as strings; they run in the page):
    - `titleReady`: the `#mw-title-enter` element exists and is not disabled and `#mw-title-screen` is not hidden.
    - `clickId(id)`: `document.getElementById(id).click()`.
    - `rollerRevealed`: `#mw-roller-cta` exists, `disabled === false`, `textContent.trim() === "DESCEND"`, and `#mw-roller-screen.hidden === false`.
    - `readReels`: `{ race, cls, sub, name, quirk }` from the five roller ids' `textContent.trim()`.
    - `clickHeroTab`: `document.querySelector('button.mw-tab[data-tab="hero"]').click()`.
    - `readHero`: `{ sName: #s-name text, sTag: #s-tag text, dossWho: #doss-who text, c: { race, cls, sub, name } from window.__mzState.get().c }`.
    - `markDead`: `const s = window.__mzState.get(); s.dead = true; window.__mzState.set(s); window.paint(); true`.
    - `returnToTitle`: `window.mzReturnToTitle(); true`.
    - `startRollAgain`: `window.mzStartRoll(); true`.

    Scenarios (each returns a row `{ scenario, reels, hero, match, notes }`; `match` is true iff `reels.race === hero.c.race && reels.cls === hero.c.cls && reels.sub === hero.c.sub && reels.name === hero.c.name && hero.sName === reels.name && hero.sTag === `${reels.race} ${reels.sub} · ${reels.cls}``):
    1. `normal` — waitFor titleReady → clickId("mw-title-enter") → waitFor rollerRevealed (20 s) → sleep 300 ms → readReels → clickId("mw-roller-cta") → sleep 300 ms → clickHeroTab → sleep 300 ms → readHero.
    2. `double-tap` — waitFor titleReady → clickId("mw-title-enter") → sleep 80 ms → clickId("mw-title-enter") again (the title is hidden by then; a programmatic click still runs its onclick, which is the same `window.mzStartRoll()` re-entry a physical double-tap produces) → waitFor rollerRevealed → sleep 3300 ms (long enough for a stale first-roll reveal timer to fire and overwrite the reels — the unfixed shell's failure mode) → readReels → CTA → HERO → readHero. Notes must record whether the reels changed between the first `rollerRevealed` and the post-sleep read (read them twice; note `reels changed after reveal: yes/no`).
    3. `play-again` — run scenario 1's steps through DESCEND (do not read the Hero tab yet) → markDead → returnToTitle → waitFor titleReady → clickId("mw-title-enter") → waitFor rollerRevealed → sleep 300 ms → readReels → CTA → HERO → readHero.
    4. `play-again-mid-reveal` (bonus row) — as 3 up to the second ENTER, then sleep 1000 ms (the race reel has locked on the first re-roll) → startRollAgain (a superseding roll mid-reveal — the death → title → ENTER re-tap) → waitFor rollerRevealed → sleep 3300 ms → readReels (twice, as in 2) → CTA → HERO → readHero.

    Output: unless `--json`, print a markdown table with the header `| Scenario | Reels shown (race / class / sub · name) | Hero tab shown (#s-tag · #s-name) | state.c (race / cls / sub · name) | Match? | Notes |` and one row per scenario (`yes`/`NO` in Match?), then a final line `roller-repro: <n>/<total> matched`. With `--json`, print the rows array. Always close the static server before exiting.
