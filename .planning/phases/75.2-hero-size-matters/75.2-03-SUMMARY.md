# Phase 75.2 Plan 03: The SIZE row, the size-honest damage bracket, and the declared hero snapshots Summary

**The hero sheet now names the hero's size (a Troll reads "Large · +2 damage, −1 vs their swings", an Elf "Small · −2 damage", a Dwarf "Small · +1 vs their swings"), and the sheet's DAMAGE range and the Hero tab's #s-dmg line both bracket the engine's real sizeDamage(c) term — the sheet can no longer disagree with a live weaponDamage() roll for any sized race.**

## Accomplishments

- **Task 1 — the SIZE row and the size term in the sheet's damage:** `src/browser/heroTab.js` gains a frozen, exported `HERO_SIZE_COPY` (label "SIZE", the damage/theirs/join/born/sep vocabulary — `theirs` reuses Phase 74's "vs their swings" phrase from `conditionEffects.js`) and a module-private `sizeRowFor(c)` that reads only `engine/derived.js#heroSize`/`sizeDamage` and formats every signed number through `src/browser/rollRange.js#signedText`/`playerDelta`, never a restated formula. Per the user's signature ruling, a damage clause appears only when `sizeDamage(c)` is non-zero and a "vs their swings" clause only when the face step is non-zero, so a Dwarf's row never claims a damage loss and an Elf's never claims to be harder to hit; a "`<race size>` by birth" clause appends when a live item step (the Gauntlet of the Giant) has moved the displayed name away from the race's own base. `characterSheetViewModel` inserts the row right after `damage`. `damageBracket` now adds `sizeDamage(c)` in the exact position `weaponDamage` applies it (right after `eff(c, "dmg")`, before the Guard/Sorcerer adjustments) — a level-1 Club Troll Soldier with prof 0/magicWpn 0 now reads DAMAGE min 13/max 18, matching a real `weaponDamage()` draw. The size imports (`heroSize`, `sizeDamage`, `SIZE_FACES_PER_STEP` from `engine/derived.js`; `signedText`, `playerDelta`, `ROLLERS` from `./rollRange.js`) sit on two SEPARATE new import lines — the pre-existing pinned `engine/derived.js` import line (`test/unit/shell-worn-slots.test.js`) stays byte-identical. `test/unit/hero-size-display.test.js` (new, 9 tests at this point) proves the row per race, the stepped and by-birth cases, the U+2212 encoding (no ASCII hyphen-minus before a digit, across all seven cases), the 200-draw damage-bracket cross-check for every sized race, and the row order (`toStrike`, `toHit`, `damage`, `size`, then every existing row unchanged). `test/unit/characterSheetViewModel.test.js` gains a Troll case in its own bracket cross-check (the file's existing Human case never exercised the size term).
- **Task 2 — the Size line on the Hero tab, the #s-dmg size term, and the declared snapshots:** `mazeworld.html` adds `<dt>Size</dt><dd id="s-size">—</dd>` right after the Damage pair in the Hero tab's `<dl class="stats">`. `renderHeroTab` writes `sizeRowFor(c).text` to `#s-size` (skipped silently when the node is absent, matching every other optional-node convention in this function) and folds `sizeDamage(c)` into `#s-dmg`'s bonus sum, so a level-1 Club Troll's `#s-dmg` reads "1² + d6 + 11". `test/unit/hero-size-display.test.js` grows to 10 tests (a `renderHeroTab` test on a real recording document, proving both DOM writes for a Troll). `test/unit/heroTab.test.js`'s `paint()` id-literal regex gains `s-size`. `test/unit/harness/shellSandbox.js`'s `SNAPSHOT_IDS.hero` gains `s-size` with a declaration comment naming the two regenerated fixtures. `MZ_SNAPSHOT_UPDATE=1 node --test test/unit/shell-tab-snapshots.test.js` touched eight fixture files; `git diff` on each of the six besides `thief.hero.txt`/`mu.hero.txt` was empty (CRLF/LF normalization noise only, the same worktree artifact 74-04's SUMMARY documents), so those six were `git checkout --`'d back — the commit carries exactly the two declared regenerations. `test/unit/shell-tab-snapshots.test.js` itself was never edited (confirmed: `git diff --quiet` exits 0). **npm test: 6458/6458, 0 failures.**
