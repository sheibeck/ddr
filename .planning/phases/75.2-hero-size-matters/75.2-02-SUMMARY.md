# Phase 75.2 Plan 02: The Gauntlet and Enlarge, one size step each, honest text Summary

**The Gauntlet of the Giant and the Enlarge potion each deliver exactly a +1 size step for their duration (RULES-11): Enlarge's separate might-kind damage payload is gone, both items' text states only what a step does, and the started event and condition chip carry the size data the shell (75.2-04) will show — with every moved bot-baseline artifact bisected live and traced to the items' rewritten flavor text, never a gameplay-decision change.**

## Accomplishments

- **Task 1 — the item rule, the event and chip fields:** `content/potions.js`'s Enlarge row becomes `act: { kind: "enlarge", effect: 50, eff: { size: 1 } }` (no `might` key) with text "one size larger for fifty squares: +2 damage, and one face easier for foes to hit"; `content/treasure-tables.js`'s Gauntlet of the Giant keeps its mechanics (`eff: { size: 1 }`, `act.kind: "giant"`) and gets the same honest wording, dropping the "mind the ceilings"/"shrinking back" promises. `engine/items.js#applyActivation` now adds `size` (the character's resulting `heroSize(c).name`), `step` (the item's own ±1) and `sizeDmg` (`SIZE_DAMAGE_PER_STEP × step`) to `itemEffectStarted` whenever the activation's `eff` carries a numeric `size`; `engine/derived.js#conditionsOf`'s live-item loop mirrors this onto the chip (`chip.step`/`chip.size`). `test/unit/size-items.test.js` (new, 14 tests) proves the item rule (ACTIVATION_OF shape, drinking Enlarge, stacking with the Gauntlet to +2 steps and refresh-not-triplicate, race signatures never masking an item's own step for a Dwarf or an Elf), the event/chip fields for Enlarge/the Gauntlet/Strength, an old save's tolerant load of a live `item:Enlarge` record (zero engine changes needed — the might amount was always read live from `ACTIVATION_OF`, never stored on the timer record), and a content guard that fails by construction if a future size item skips the honest wording or carries a `might` key alongside `size`. `test/unit/item-activation.test.js`'s Strength+Enlarge stacking test is restated (`potionMight` 8, `sizeStepOf` 1); `test/unit/conditions.test.js` gains a proof that a live Gauntlet chip carries `step`/`size` and a haste chip carries neither.
- **Task 2 — docs, the store snapshot, fixtures, and the moved bot-baseline artifacts:** `docs/USABLE-FEATURES-AUDIT.md`'s Enlarge row becomes `itemUsed` (size +1, 50 squares); `docs/GEAR-BALANCE.md`'s Enlarge/Gauntlet rows and the might-chip row are restated to the new truth, with a RULES-11 citation. `test/unit/fixtures/shell-snapshots/thief-store.store.txt`'s Enlarge row is regenerated (its italic text follows the rewrite) and declared in `shell-tab-snapshots.test.js`'s header — the other seven committed fixtures confirmed byte-identical.
