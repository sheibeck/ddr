<objective>
Establish the engine boundary — the GameState factory (newRun), the Action/Event contracts,
and the pure `applyAction(state, action) → {state, events}` dispatcher with input validation —
and land the first rule domain behind it: character generation, derived character numbers, and
leveling. This is the spine every later slice plugs into.

Purpose: ENG-01 requires all rules reachable only through one pure entry point with no DOM/
render/storage inside. Character generation is the natural first domain because newRun MUST
produce a rolled character (and a floor via maze.js), so the skeleton cannot move without it.
Derived numbers (strikeDie/toHit/weaponDamage/upkeep) and checkLevel are shared by combat,
movement, and magic, so they belong in this foundation. Action validation at the single chokepoint
is the phase's one real security control (V5 input validation).

Output: engine/state.js, actions.js, events.js, engine.js, character.js, derived.js + the
engine-purity test, a character unit test, a same-seed determinism test, and the chargen parity
fixture proving newRun matches the prototype.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| caller → applyAction (action input) | An `action` object reaches the engine from the presentation layer (or, later, a network peer). It is untrusted: a UI bug or malformed message must not throw or corrupt GameState. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-05a | Tampering / Denial of Service | applyAction action input | low | mitigate | validateAction checks type + field shapes at the single chokepoint; unknown/malformed actions are no-ops returning unchanged state, never throwing (V5 input validation). |
| T-01-05b | Tampering | non-serializable data entering GameState | low | mitigate | structuredClone in applyAction is NOT wrapped in try/catch; a stray closure fails fast, preventing a non-serializable value from silently entering state (protects ENG-04). |

No package installs (T-01-SC N/A). Save-file/localStorage validation is handled in plan 01-06.
</threat_model>
