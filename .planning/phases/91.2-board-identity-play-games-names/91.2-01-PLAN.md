  <action>
    Per D-02, create `PlayIdentityPlugin.java` in package `com.darktierstudios.delvedierepeat`: a class annotated `@CapacitorPlugin(name = "PlayIdentity")` extending `com.getcapacitor.Plugin`, with four `@PluginMethod` methods:
    - `init`: calls a private `ensureInit()` that runs `PlayGamesSdk.initialize(getContext())` once (a boolean guard), then resolves `{ ok: true }`; on any exception resolves `{ ok: false, reason: "error" }`.
    - `status`: `ensureInit()`, then `PlayGames.getGamesSignInClient(getActivity()).isAuthenticated()`; when the task fails or the result is not authenticated, resolve `{ ok: true, signedIn: false }`; otherwise fetch `PlayGames.getPlayersClient(getActivity()).getCurrentPlayer()` and resolve `{ ok: true, signedIn: true, playerId: player.getPlayerId(), displayName: player.getDisplayName() }` (a failed player fetch resolves `{ ok: false, reason: "error" }`).
    - `signIn`: `ensureInit()`, then the interactive `GamesSignInClient.signIn()`; resolve exactly like `status` from its `AuthenticationResult`.
    - `serverAuthCode`: read `serverClientId` from the call; empty or missing resolves `{ ok: false, reason: "config" }`; otherwise `ensureInit()` and `GamesSignInClient.requestServerSideAccess(serverClientId, false)` (the two-argument, no-extra-scopes overload: never request PROFILE, EMAIL or OPEN_ID, which expose the real name and email); success resolves `{ ok: true, authCode }`, failure `{ ok: false, reason: "denied" }`.
    Every method resolves with `call.resolve(JSObject)` and never calls `call.reject`. Never log the player id, the display name or the auth code. The class header comment explains: lazy init (the SDK starts only when JS calls a method, and the shell only calls it while Compete is ON); the documented A6 fallback if lazy init fails on the device (call `ensureInit()` from `load()` when the Capacitor Preferences group "CapacitorStorage" holds settings with Compete ON); and that `SUPPRESS_GAME_PROFILE_CREATION` is deliberately not set.
