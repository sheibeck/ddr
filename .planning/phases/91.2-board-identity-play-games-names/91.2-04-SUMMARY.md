## What changed

- **Final rules.** `namePath` / `isNamed` / `verifiedName`; `isValidBoardRun`'s handle clause is a string of 1..64 characters (no regex anywhere); the runs create adds `isNamed(request.auth.uid) && request.resource.data.handle == verifiedName(request.auth.uid)` (isNamed first) and keeps the banned check; runs `allow update: if false;`; delete stays the owner's; `match /names/{uid}` and `match /nameOverrides/{uid}` are `allow read, write: if false;`. Header and `isValidBoardRun` comment rewritten.
- **Transition rules.** The final file plus exactly: Phase 87's either-formula deepKey clause, `isLegacyHandle` (the verbatim 2.2.0 regex), one legacy create disjunct (unnamed uid, `isLegacyHandle`, banned check kept), and the legacy handle-only update (`!isNamed`, owner, `affectedKeys().hasOnly(['handle'])`). Both legacy branches carry `!isNamed(request.auth.uid)`. The header (BEGIN/END markers kept) says what it accepts, that one deploy covers it and the still-pending Phase 87 deploy, that it goes with the final rules at Release 2.3.0, and what to delete.
- **Proof of minimality.** `test/unit/firestore-transition-rules.test.js` reduces the transition text by those four things plus the header and compares to the final file byte for byte; it also pins `!isNamed` in both legacy blocks, that `isLegacyHandle(` is called from exactly those two places, and that the regex equals `LEGACY_HANDLE_PATTERN`, which equals a literal 2.2.0 regex held in the test.
- **runDoc.js.** The rolled-handle import is gone; `validateRunDoc(doc, { uid, now, name })` passes a handle of 1..`BOARD_NAME_MAX_CHARS` characters and, when `name` is a string, equal to it (fail id stays `handle`); `LEGACY_HANDLE_PATTERN` / `isLegacyHandle` sit beside `legacyDeepKeyOf`, transition-only. `handleUpdateCommit` kept (boardWrites still imports it until 91.2-05).
- **Fake server.** Default = final rules: a client create needs a names entry and `handle == name`, no client run update, owner delete and ban still work. `transition: true` = transition rules: either deepKey, a 2.2.0 `@handle` create from an unnamed uid, the legacy re-roll for an unnamed owner; a named uid can never use a legacy branch. Admin paths untouched and never reach a client rule. The old Phase 87 option name no longer appears in `src`, `tools` or `test`.
- **boards-smoke.** Default probe steps (all PASS against the fake): signup, deny-unnamed-create, seed-name, create-a, create-b, resubmit-a, top-ten, totals, ranks, deny-bad-key, deny-other-id, deny-no-auth, deny-wrong-name, deny-update, deny-names-read, deny-names-write, deny-list-51, ban, admin-delete, erase, account-deleted; cleanup removes runs, the names doc and the account. `--transition`: signup, create-legacy (also the unnamed re-roll), deny-third-key, seed-name, create-named, deny-legacy-when-named (create and re-roll), erase, account-deleted. `--function`: signup, claim-unlinked (refused NOT_LINKED), release (ok), account-deleted, no admin needed. Docs are built with `buildRunDoc(summary, { uid, handle: <explicit name>, version })` and posted with `createRunCommit` through the smoke's own bearer helper; resubmit-a proves idempotence with an ambiguous answer then one public GET under the probe uid; `writes.eraseMyRuns` kept for erase. Admin auth resolved up front (exit 2 and an "admin seed" message without it). "Never another project", the finally-cleanup and the exit codes are kept.

## Shipped 2.2.0 client compatibility (transition rules)

A vc12 client does an anonymous sign-up, a `createRunCommit` with an `@handle` and the old deepKey, a handle-only `:commit` update (mask `handle`, `exists: true`) and owner deletes. Under the transition rules: the create lands (unnamed uid, `isLegacyHandle`, either deepKey formula, banned check), the re-roll lands (unnamed owner), delete is unchanged, reads are unchanged. Under the final rules all three writes are refused, silently (D-13). Once an anonymous uid becomes named, neither legacy branch can be used and its old runs can only move through the function's adopt path (IAM).
