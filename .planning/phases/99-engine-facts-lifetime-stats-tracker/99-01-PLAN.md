<objective>
Add the two engine facts the achievements need and nothing else: a `group` field on `foeKilled` (the BESTIARY family the foe was drawn from) and a `wp` field on `afflictionCaught` and `afflictionTick` (the hero's HP right after that hit). Both are additive, read values the engine already holds, and draw no dice. Then prove the engine gate holds: parity byte-identical, zero fixtures moved, the prototype master untouched.

Purpose: ROADMAP Phase 99 success criterion 1 and TRACK-01. Every other fact the 77 achievements need is already in the engine's events and state (CONTEXT D 'Engine facts': depth, days, wilmst, worn slots, race and parent class, `died` cause, `fled` reason `escaped`, `parleyWon`, `joinerJoined`, `memberDowned`, `joinerMurdered`, `trapSprung`, `potionDrunk`, `walkingDeadTurned.count`). The kill group is needed because `foeKilled` carries only a name and an elite's name is titled ("Dread Ogre"), so a name lookup would be fragile; the post-hit HP is needed because Terminal Condition is "exactly 1 HP after a Disease (or Poison) hit", and the state after the whole action is wrong whenever something else in that action also changes HP.

This is the milestone's only plan that moves engine bytes. Plan 99-02 (the tracker) reads these field names by contract and runs in parallel with this plan; plan 99-03 (the adapter) runs after both.

Output: three one-line engine edits with their comments, one new test file, and a SUMMARY that declares zero moved fixtures.
</objective>
