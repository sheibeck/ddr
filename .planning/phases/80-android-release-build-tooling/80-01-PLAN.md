<objective>
Turn on R8 for the release build (minify, resource shrinking, obfuscation) on the pinned AGP 8.13.0 toolchain, prove it with a real release build, and document the deobfuscation mapping.

Purpose: DROID-01 / ROADMAP Phase 80 success criterion 1. The research (80-RESEARCH.md "R8 / DROID-01") showed the keep rules the WebView bridge needs already ship with the dependencies (Capacitor core's consumer rules, the Play Games plugin's consumer rules, AGP's default JavascriptInterface keep). This plan adds a defensive mirror of them, proves them against a real build's mapping.txt instead of by reasoning, and closes one gap the research did not cover: the splash-screen plugin loads its drawable by name, which the resource shrinker cannot see.

Output: the release build config, the keep rules and keep.xml, a source-level test, verified R8 build outputs, and the RELEASING.md R8 section.
</objective>

## Flagged assumptions (surfaced, not silently decided)

- **DROID-01, edge probe: unclassified, reviewed manually.** The probe proposed no data-shape edges. The real edges are the reflective entry points R8 cannot see (plugin classes loaded with Class.forName from capacitor.plugins.json, @PluginMethod methods found by annotation, JavascriptInterface methods called from JS) and resources loaded by name. Each has an explicit mapping.txt / aapt2 check in Task 2. Runtime correctness on a device is not provable from build output; the emulator smoke (80-05) and the Pixel 7 milestone-close smoke are the runtime gates.
- **Default ProGuard file choice.** This plan keeps `proguard-android.txt` (R8 shrinks and obfuscates but does not run the extra optimisation passes), the lower-risk option for a release whose device smoke is deferred to milestone close. The research rated `proguard-android-optimize.txt` equally defensible. The deferred AGP 9 upgrade will have to switch to the optimize file; RELEASING.md records that.
- **Canon referral (not minted as a prohibition):** signing secrets (android/keystore.properties, any .jks) are never copied into a worktree or committed. Standard secret handling, stated in the build-environment note below.

<environment>
Android/Gradle builds read git-ignored files that exist only in the main checkout C:/projects/mazeworld:
- node_modules/ (the Capacitor Gradle projects point into ../node_modules), android/local.properties (one line, sdk.dir=C:/Users/Dell/AppData/Local/Android/Sdk), and, for signing only, android/keystore.properties.
- In a fresh git worktree: run `npm ci` first, then create android/local.properties holding only the sdk.dir line copied from the main checkout (not a secret).
- Never copy, create or commit android/keystore.properties or any .jks. Without it the release build is unsigned, and R8, mapping.txt and the AAB's BUNDLE-METADATA are identical signed or unsigned.
- Build only through the npm scripts and tools/gradle.mjs. `npx cap sync` wipes org.gradle.java.home and `node tools/pin-jdk.mjs` re-applies it; `npm run android:release` already chains build:www, cap sync, pin-jdk and bundleRelease.
- Before committing: `git diff --exit-code -- android/gradle.properties android/version.properties android/app/capacitor.build.gradle android/capacitor.settings.gradle` must be clean (this plan changes no plugin list).
