## Flagged assumptions (surfaced, not silently decided)

- **DROID-01, edge probe: unclassified, reviewed manually.** The edges are the reflective entry points R8 cannot see (plugin classes loaded with Class.forName from capacitor.plugins.json, @PluginMethod methods found by annotation, JavascriptInterface methods called from JS) and resources loaded by name. This plan pins the rules statically; 80-04 checks each against the single build's mapping.txt and aapt2 output; 80-05 and the Pixel 7 smoke are the runtime gates.
- **R8 surprises surface only at the single build.** R8 may stop on missing classes the first time it runs. Under the one-build ruling, 80-04 does not patch config and rebuild; it stops and records the gap (with R8's missing_rules.txt) for a code-part gap-closure plan, followed by a fresh single build.
- **Default ProGuard file choice.** `proguard-android.txt` (shrink and obfuscate, no extra optimisation passes) is kept: the lower-risk option for a release whose device smoke waits for milestone close. The deferred AGP 9 upgrade must switch to `proguard-android-optimize.txt`; RELEASING.md records that.
- **Scanner fixture source.** The scanner test uses a real `dexdump -d` excerpt from the existing debug APK at C:/projects/mazeworld/android/app/build/outputs/apk/debug/app-debug.apk (built 2026-09-24, still containing the status-bar plugin's setStatusBarColor call). Reading an old artifact is not a build. The mapping.txt lines in the test follow R8's documented format; 80-04 confirms the parser against the real mapping (zero unresolved obfuscated callers).
- **Canon referral (not minted as a prohibition):** signing secrets (android/keystore.properties, any .jks) are never copied into a worktree or committed.
