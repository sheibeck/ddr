# Phase 80 Plan 02: SystemBars Migration (CODE part) Summary

**Uninstalled the deprecated `@capacitor/status-bar` plugin entirely and moved bar styling to Capacitor 8's core `SystemBars` plugin, with the native Gradle project regenerated by `cap sync` — no build ran.**

## Accomplishments

- `src/browser/nativeChrome.js#registerNativeChrome` now resolves `SystemBars` via a guarded dynamic import of `@capacitor/core` and calls `SystemBars.setStyle({ style: "DARK" })` — no colour call of any kind, matching Android 15's deprecation of bar-colour APIs.
- `@capacitor/status-bar` is uninstalled from `package.json`/`package-lock.json` and dropped from `tools/build-www.mjs`'s `CAPACITOR_PACKAGES` vendoring list.
- `npx cap sync android` (via `npm run cap:sync`, code generation only — no Gradle task) regenerated `android/app/capacitor.build.gradle` and `android/capacitor.settings.gradle`; both diffs are removed-lines-only. The git-ignored `android/app/src/main/assets/capacitor.plugins.json` no longer lists the status-bar plugin (confirmed by both a source pin and the plan's ad-hoc verify command).
- `capacitor.config.json` gained a `plugins.SystemBars` block (`insetsHandling: "css"`, `style: "DARK"`) so the style is correct from the very first native frame, before JS ever runs.
- `styles.xml`'s `AppTheme.NoActionBar` now sets `colorPrimaryDark` (`#1b170f`) and `android:windowBackground` (`#14110c`) — non-deprecated theme attributes covering the Android 7-14 path (where edge-to-edge is not forced) and the WebView's background on Android 15+ respectively. Neither Android-15-deprecated bar-colour attribute (`android:statusBarColor`/`android:navigationBarColor`) is set.
- New `test/unit/android-system-bars.test.js` pins both halves of the migration: the web-shell source (Task 1) and the native/dependency state (Task 2) — 14 tests, all green.
- `test/persistence/lifecycle.test.js`'s three `StatusBar`-named tests are migrated to `SystemBars`, plus one new DROID-02 test asserting the exactly-once `DARK` call with the background-colour spy left uncalled.

## Decisions Made

- Uninstalled the package outright rather than just dropping the JS call, per the plan's "Research correction" section: `StatusBarPlugin.load()` sets the deprecated colour on every native launch via its own constructor, independent of any JS call, because it's registered in `capacitor.plugins.json`.
- Chose `@capacitor/core`'s `SystemBars` over any replacement standalone plugin — it's auto-registered (`Bridge.registerAllPlugins()`), needs zero new npm dependency, and already handles the `--safe-area-inset-*` CSS injection `mazeworld.html` needs.
- Kept the `styles.xml` edit scoped to exactly the two theme attributes named in the plan (`colorPrimaryDark`, `android:windowBackground`) on `AppTheme.NoActionBar` only — `AppTheme` and `AppTheme.NoActionBarLaunch` are untouched, as required.
