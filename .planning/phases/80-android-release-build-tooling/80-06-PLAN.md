## Flagged assumptions (surfaced, not silently decided)

- **TOOL-01, edge probe: unclassified, reviewed manually.** The edges are the infeasible point at the first probe (n=2), a block boundary right after it (block 1 stops at n=3, block 2 resumes at n=4), a logged row whose dials do not match (already unit-tested: re-evaluated fresh), and repeated blocks against one log and one transcript. The CLI test covers the first two and the transcript; the library test covers the dials-mismatch case.
- **Why a test seam:** classConstraints treats any class with fewer than 20 runs as unconstrained (CLASS_POOL_MIN_N), so no search cheap enough for `npm test` can ever produce a real infeasible candidate. `--force-infeasible` marks listed candidates as rejected through the same constraints.ok path the real rejection uses, so the CLI test exercises the real Infinity to null to Infinity round trip. It is labelled test-only and refused outside --search.
- **Where the test lives:** test/difficulty/ (run by `npm test`, not by `npm run test:quick`), because it spawns the real engine for about a dozen tiny evaluations.
