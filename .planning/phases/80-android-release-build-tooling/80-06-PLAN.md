## Flagged assumptions (surfaced, not silently decided)

- **TOOL-01, edge probe: unclassified, reviewed manually.** The edges are the infeasible point at the first probe (n=2), a block boundary right after it (block 1 stops at n=3, block 2 resumes at n=4), a logged row whose dials do not match (already unit-tested: re-evaluated fresh), and repeated blocks against one log and one transcript. The CLI test covers the first two and the transcript; the library test covers the dials mismatch.
- **Why a test seam:** classConstraints treats any class with fewer than 20 runs as unconstrained (CLASS_POOL_MIN_N), so no search cheap enough for `npm test` can ever produce a real infeasible candidate. `--force-infeasible` applies the same rejection shape both row builders produce (evalRow and tailEvalRow: score Infinity, verdict MISS, constraints.ok false, a joined reason), so the CLI test exercises the real Infinity to null to Infinity round trip. It is labelled test-only and refused outside --search.
- **Where the test lives:** test/difficulty/ (run by `npm test`, not `npm run test:quick`), because it spawns the real engine for about a dozen tiny evaluations.
- **Parallel with the gameplay phases:** Phase 75.3 already added `--objective=tail` to this CLI, and 79.1 will run it. Keep the edits to parseArgs (two cases), usage (two lines), the header's flag list and run examples, and main()'s stdout routing, block header and the seam in realEvaluate; re-read the file at execution time, since it may have changed again.
