- **No wholesale comment-volume purge** — Phase 47's line-budget ruling closed that. This phase removes stale *meaning*, not comment volume. A comment that explains a retirement by name ("was a toast; the rail owns feedback since Phase 35") stays when it still helps a reader — it must not describe the retired thing as live.

- **Windows executor environment:** Git Bash, no `jq`; `mazeworld.html` is CRLF in the working copy (preserve CRLF — edit with the Edit tool, never rewrite the file through a script that normalises line endings; `git diff --stat` must show only the lines you meant); heredocs and `node -e` one-liners mangle backslashes — write any regex-heavy script to a file with the Write tool, never a heredoc.
- **Line numbers drift:** anchor by the quoted text; numbers below were measured at HEAD `649de2b`.
- **Verification agents are off:** the acceptance criteria ARE the verification — every `<verify>` command is literal, with its expected output.
- **Test bodies: the bounded rule.** The CONTEXT says "test bodies and assertions are not touched (a body that needs changing is a behaviour question — flag it, don't fix it here)". This phase reads that as: no expected value, condition, fixture literal, event type or field name changes. Two edits are NOT behaviour questions and ARE in scope (Plans 03-04): (i) renaming a local identifier whose name contains `toast`/`Toast`/`TOAST` to its `line`/`Line`/`LINE` equivalent, consistently within its scope; (ii) rewording an assertion MESSAGE string. A test TITLE is not a body: rename it. A comment inside a body is a comment: rewrite it. If a rename or comment rewrite trips another test that pins the old text: reword so the pinned substring survives when it is not itself stale; if it IS the stale text, revert and list the line as a survivor with the pinning test's name — never edit an expected value.
