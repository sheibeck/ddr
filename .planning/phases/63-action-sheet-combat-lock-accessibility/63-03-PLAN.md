<objective>
This plan does two things.

1. Close a gap in "every completed action's outcome reaches the player through the rail in voice" (GSCR-09). Today `itemDropped` and `itemUnequipped` are ORACLE_ONLY in `src/browser/narrationLines.js`, with the rationale that the inventory screen's own drop/unequip action is the UI signal. Under the sheet that rationale no longer holds: the sheet closes and the rail is the one feedback surface. So DROP, UNEQUIP and DISCARD would land silently. This plan gives both events LINE_FOR lines. It is a presentation-only change in `src/browser/`, and the engine emits exactly the same events.
2. Prove Plan 01's model agrees with the engine, using a sweep that dispatches every sheet action's `run` through the real `applyAction`. Every greyed reason must be the engine's own refusal. Every live action must produce a rail or fight-log line. GRULE-02's "after the fight they work again" must hold.

Purpose: GSCR-09's "states the engine's reason" and "outcome reaches the rail" become proven properties, not assumptions. This runs in wave 3 in parallel with Plan 04, which shares none of these files. It waits for Plan 02 so that `src/browser/gearSheet.js` is settled. That file is touched here only if the sweep exposes a real model/engine disagreement (a Rule 1 fix).

Implements CONTEXT "Outcome goes to the rail only … the engine events reach the rail through the existing narration fold". This plan makes that fold cover drop and unequip. It also implements "Combat lock … After the fight, everything works again".
</objective>
