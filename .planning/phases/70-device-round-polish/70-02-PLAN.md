<objective>
Turn the LINEAGE leaderboard from one row per race-and-class combination into the top 10 runs for one lineage (POLISH-04). A race selector and a sub-class selector sit at the top of the board and default to the active hero's lineage. Below them, the list shows the ten deepest runs of exactly that lineage: locally from the device's own runs, and, when signed in, filtered from the cached 25-entry DEEPEST sample.

This plan is the validated draft quick plan `260924-5b8`, reused per D-14 and executed as written with Phase 70 IDs. The draft file is provenance only; this plan supersedes it.

Purpose: user device feedback, 2026-09-24: "lineage doesn't quite work unless you have a selector to choose the lineage. We should be able to choose race and sub class and then see top 10 for that selection. It should default to whatever your current race selection on your active character are."

Output:
- engine/records.js: records support for a correct per-lineage top ten over time;
- boardsView.js and content/boards.js: the new LINEAGE view model and copy;
- boardsPanel.js: the picker in the panel;
- mazeworld.html: the shell wiring and CSS;
- tests for all of the above, and the SUMMARY.

Precondition (D-01): quick task 260924-51h (POLISH-01) is already merged into master (commit c8e25d3). Branch from that master; touch no title-music code.

Wave note: plan 70-01 runs in parallel in this wave and owns src/browser/hudMenu.js, src/browser/account.js, content/account.js, src/browser/accountChip.js, test/voice/safety-scan.test.js and test/unit/hp-not-wp.test.js. Decisions implemented (locked, from 70-CONTEXT.md):
- D-09: race and sub-class chip rows (44px targets that fit 411px at S/M/L); the top 10 runs of that lineage in DEEPEST order; the NOT IN THE TOP TEN · YOUR BEST RUN pin; a lineage standing card; an in-voice empty note.
- D-10: lineage = race + sub (the displayed "RACE SUB"), not race + cls. lineageKey changes accordingly.
- D-11: the default is the active hero's race + sub. With no live hero it is the most recent run's lineage; with no runs, the first in content order. It re-defaults on every panel open.
- D-12: engine/records.js prune keeps each lineage's top 10 runs in ddr.bests.v1. There is no GameState change, parity is untouched and old saves tolerant-load. The Phase 65 lineage {count, best} map is retired. LINEAGE new-best keeps the 65 D-14 strict-beat rule, computed from the kept runs.
- D-13: global LINEAGE filters the existing cached 25-entry DEEPEST sample (the plugin cap) to the selected lineage, with an honest footnote and no new network calls.

Sub-class ruling (verified in code): `cls` is the base class (Magic User / Fighter / Thief, the content/classes.js CLASSES keys). `sub` is the sub-class (Wizard, Knight, Pickpocket, …, from CLASSES[cls].subs). Greenfield: the old one-row-per-lineage view, its lineage {count, best} aggregate map and its copy are removed, with no dual path.

Records ruling (per D-12): the existing stores cannot yield a correct per-lineage top ten over time. The graveyard caps at 60, and prune deletes any run that falls off every ranked board. So prune itself keeps each lineage's top BOARD_TOP_N runs, grouped by the new lineageKey and ranked by lineageRuns. By induction, every lineage's true top ten from the day this ships is always held in ddr.bests.v1's runs map; the view derives the list from those runs, and no new field is written. The record stays v 1. Storage stays bounded: at most 10 runs per distinct lineage (6 races × 24 sub-classes = 144) on top of the five boards.
</objective>
