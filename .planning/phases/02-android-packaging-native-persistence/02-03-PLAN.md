## Phase Goal

**As a** Mazeworld player, **I want to** my run saved after every move and whenever I background the app, and the back button to never dump me out of a live delve, **so that** an interruption or a mistaken back-press never costs me my run.

*(Derived from the ROADMAP Phase 2 `**Goal:**` line under MVP_MODE. This slice makes save/resume and lifecycle safety real: it routes ALL persistence through the durable abstraction from 02-01 and adds the back-button + lifecycle-flush behavior.)*

<objective>
Converge every save/load path onto the one shared `window.mzStorage` abstraction (fixing the Phase-1 dual-write hazard), make the adapter's autosave async-safe, and add the Android back-button + app-lifecycle logic — all as pure, node-testable units with the native plugins mocked.

Purpose: Deliver SAV-01/02 (autosave after every action AND on background; exact resume), keep SAV-04/05 (best depth, graveyard) on the durable store, and satisfy PLT-02 (back button never silently ends a run) and PLT-03 (lifecycle persists + resumes). The dual-write fix is load-bearing: the classic script still owns all combat/economy saves (Phase 1 left those un-ported), so leaving it on raw localStorage would silently reintroduce the durability risk this phase exists to close.

Output / artifacts this plan produces:
- `src/browser/nativeChrome.js` — pure `decideBackAction(...)`, an awaited `flushOnBackground(...)` handler, and a native-only `registerNativeChrome()` that dynamically imports and wires the plugins.
- Refactored `src/browser/engineAdapter.js` (async boot/getBest, storage-routed persist/recordBest/persistGrave) and `mazeworld.html` (trailing module orchestrates storage assignment + migration + restructured classic boot).
- `test/persistence/{dual-write-convergence,lifecycle,back-button-logic}.test.js` and an updated `test/unit/engineAdapter.test.js`.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| OS lifecycle (background/kill) → app state | the OS can suspend/kill the process at any time; the last write must complete before that |
| hardware back button → run state | an OS-level back-press must not be able to destroy a live run |
| stored save → app on resume | resumed save is untrusted input (reuse fail-closed validation) |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-02-04 | Tampering (self-inflicted, torn write) | pause/appStateChange flush racing OS suspension | high | mitigate | flushOnBackground AWAITS storage.flush() inside the handler (not fire-and-forget); storage's per-key queue orders writes; validateSave is the backstop if a hard-kill still tears a write |
| T-02-05 | Tampering | back button silently ending a run | high | mitigate | decideBackAction returns confirm-quit before any exit-app; registering a backButton listener disables Capacitor's default entirely so the app owns 100% of back semantics; unit-proven no silent run-end |
| T-02-01 | Tampering | resumed run save from storage | medium | mitigate | boot() validates via engine/saveState.js validateSave (unchanged) and falls open to a fresh run on malformed/tampered/newer-version data |
</threat_model>
