Positional, cost-preserving reshape (RESEARCH Option A, D: "Table reshape rule"). Object-literal position 1..N, old key -> new key, cost unchanged, `active` id where the entry becomes an active, `txt` = the catalog txt for actives (kept passives keep their exact current txt/txt2/up):

`splitTableAbilities(c)`: for each key of `c.skills` whose table entry has `active`, push the id to `c.abilities` (in `c.skills` key order) and delete the key from `c.skills`. `c.vp` is untouched. Idempotent. Magic Users (no table) are a no-op.
</table_reshape_spec>
