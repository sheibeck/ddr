<objective>
Bind Phase 68's leaderboard calls behind the Phase 67 provider seam, in both the native provider and the in-memory fake. Implements D-01 (a validated submit with the score tag), D-05 and D-06 (top scores for the public and friends collections, the player's own score, and the friends-consent check and request), D-07 (every call resolves, never rejects, and times out instead of hanging, so the panel and queue never block) and D-10 (the DEEPEST rank and score count used by the rank line). The method names are Claude's discretion per 68-CONTEXT; they replace 67-02's RESERVED_LEADERBOARD_METHODS, which is retired now that the calls are bound (greenfield: the placeholder list and its test go).

Plugin facts this plan relies on (read-only review of @modbender/capacitor-play-games 0.5.0 during planning; 67-01's review file is authoritative when it exists): submitScore({ leaderboardId, score, scoreTag? }) resolves only after the server write, with results[] per time span each carrying newBest; loadTopScores / loadPlayerCenteredScores take { leaderboardId, timeSpan (default allTime), collection (default public), maxResults (default 25, range 1-25, no paging binding), forceReload } and resolve { leaderboard, scores, stale }; loadCurrentPlayerScore resolves { score: LeaderboardScore | null }; loadLeaderboard({ leaderboardId, forceReload }) resolves { leaderboard } whose variants carry playerRank and numScores; loadFriends({ pageSize, forceReload, resolve }) resolves { friends, stale, resolutionRequired } and shows the consent UI only with resolve: true. A LeaderboardScore carries rank?, rawScore, scoreTag, scoreHolder (PlayerInfo with playerId, displayName, friendStatus), scoreHolderDisplayName and image URLs.

Purpose: one seam for every Play Games leaderboard call, testable without a device.
Output: the extended src/browser/playGames.js and its tests.
</objective>
