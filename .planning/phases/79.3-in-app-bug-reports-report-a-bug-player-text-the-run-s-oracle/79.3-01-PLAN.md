## Flagged assumptions

- **The rules can't run offline.** There is no emulator and no npm install, so the rules are checked two ways:
  - statically, against the client constants (Task 2);
  - live, by `--probe-rules` in 79.3-08.
  `validateReport` in bugReport.js is the JS mirror of the rules, so the builder never produces a payload the rules would refuse.
- **String lengths.** JS `length` counts UTF-16 units, which is never fewer than Firestore's `size()` characters, so a JS cap is always inside the rules cap. Every clamp drops a trailing lone high surrogate so no invalid UTF-16 is ever sent.
- **No copy in these modules.** The voice corpus's raw sweep reads every string literal in src/browser. These two modules must hold no sentence-like literal (nothing with a space, and nothing ending in `.`, `!` or `?`). Failure reasons are ids, and all player copy lives in 79.3-05's bank.
