# Phase 93.1: Gauntlet of the Giant Worth Wearing - Context

**Gathered:** 2026-10-03
**Status:** Ready for planning

<domain>
## Phase Boundary

ITEM-09: the unfixed half of GitHub player report #6 (sheibeck/ddr#6, 2.1.0, "Enlarge potion worthless. +2 damage to get hit more often?", plus the owner's comment "Same thing with Gauntlet of the Giant"). Enlarge was fixed in 2.3.0 (Phase 89, ITEM-05: +9 bulk on top of the size step's +2, so +11 for 50 squares, foes +1 to hit). The Gauntlet of the Giant is still the bare size step: +2 damage and foes +1 to hit for 50 squares, then 50 squares to recover.

This phase gives the Gauntlet a bulk bonus and moves every place that states its numbers with it. It is a content and number change only: no new rule, no main-rng draw, and no new event type.

Not in this phase: closing GitHub issue #6. That happens when the release carrying the fix ships (the 2.4.0 release step). Also out: any other item, the economy, and the flavour rewrite of the text (Phase 95 rewrites item text once, on top of this phase's rules text).

</domain>

<decisions>
## Implementation Decisions

### The Gauntlet's numbers (user, 2026-10-03)
- **+6 damage in all: the size step's +2 plus +4 bulk.** It is smaller than Enlarge's +11 because the Gauntlet recharges while the potion is used up. It is carried the way Enlarge carries its bulk (the activation's `eff`, e.g. `{ size: 1, dmg: 4 }`, read by the same size and damage path), so the "Enlarged" chip's `dmgTotal` reads 6.
- **The cost stays one size step:** foes +1 to hit the wearer (SIZE_FACES_PER_STEP), as today.
- **Window and cooldown unchanged:** 50 squares on, 50 to recover (once every 100 squares).
- **Price unchanged:** 1,200 in `engine/economy.js`.
- **Stacking follows Enlarge:** a Troll wearing it stacks exactly as a Troll drinking Enlarge does. Whatever the engine does today when the Gauntlet and Enlarge are both live is kept (no new stacking rule).

### Carried by the roadmap (locked)
- Joiners get the same numbers: the Gauntlet stays in `MEMBER_COMBAT_KINDS` (their round-1 opener), and taking it off ends the effect as today.
- One count everywhere: the item `txt`, the "Enlarged" chip and its CONDITION_EXPLAIN line (`mazeworld.html`), the Gear, store and find cards, the `docs/ITEM-AUDIT.md` row (plus a dated Rulings bullet, which must not start with `- Q`), the 2.4.0 DRAFT patch notes (`docs/patch-notes/2.4.0.md`, started in Phase 93), and the fair bot's read (`tools/lib/tuning-bot.mjs` round-1 buff list).
- A seeded run that never uses the Gauntlet plays out identically. Any fixture that moves is measured, declared in `test/parity/FIXTURE-INVENTORY.md` (Phase 93 plan 02 section as template) and regenerated, with only those fixtures touched.

### Claude's Discretion
- The exact `eff` field shape (reuse Enlarge's `dmg` bulk field so the existing size-damage path reads it).
- Exact wording of the rules text in the house voice. Suggested: "used, you are one size larger for fifty squares: +6 damage, and foes +1 to hit you; then fifty squares before it will do it again".
- Whether a one-rule guard test like Phase 93's `cloak-one-rule.test.js` is worth adding for the Gauntlet (recommended if cheap).

</decisions>
