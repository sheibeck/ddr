## Typography

Rem-based scale with an S/M/L multiplier satisfying UX-08 (all four roles scale together from one root multiplier — never independently).

| Role | Size (M / base) | Weight | Line Height | Font |
|------|------|--------|-------------|------|
| Micro-label | 0.5rem (8px) | 400 | 1.5 | Press Start 2P — HUD tags (FLOOR/DAY/SQUARES/RATIONS), tab labels, button labels, section headers (THE DOOMED / GEAR / CARRIED / GRAVEYARD / THE ORACLE / MARKS legend), skill names, stat-row keys |
| Body | 0.9375rem (15px) | 700 | 1.5 | Courier Prime Bold — running/flavor text: quirks, skill descriptions, gear descriptions, log/Oracle lines, epitaphs, camp sheet copy, legend descriptions |
| Data | 1rem (16px) | 700 | 1.2 | Courier Prime Bold — numeric HUD values (floor/day/squares), WP labels, stat values, wilmst counts, log dice-roll text |
| Display | 0.8125rem (13px) | 400 | 1.6 | Press Start 2P — character name, screen identity headers (THE ORACLE / THE DOOMED as titles), foe name/encounter title, death-card name, roll-reveal name |

**Text-size setting (UX-07/UX-08):** S = 0.85×, M = 1.0× (values above), L = 1.25× — applied as ONE root multiplier (e.g. a `--mw-text-scale` CSS custom property multiplying every `rem` token) so all four roles move together. Persist as `mazeworld.textSize` ('S'|'M'|'L') via `window.mzStorage`. Also honor the OS font scale, clamped to this same 0.85–1.25× range so an extreme OS setting can't break the pixel-art layout.

**Maze canvas cell size** (folds the mockup's raw `cellSize` slider into text-size, per CONTEXT.md — not exposed as a separate setting): S = 28px, M = 34px (mockup default), L = 40px logical CSS px, before DPR multiplication. Feature-mark icon draw size = `Math.round(cellSize * 0.6)`, matching the mockup's glyph-to-cell ratio (`fontSize: cs * 0.6`).

**Colorblind-safe contract (UX-08):** every color-coded state above ALSO carries a non-color signal — never color alone:
- Rations low: red text/bar **+** the numeric "RATIONS n" label **+** (recommend) a small ration-icon that visibly depletes, not just a red bar.
- Trap: the `trap.png` icon shape **+** the "TRAP" flash text label — red tint is reinforcement only, never the sole cue.
- WP/health bars (player + foe): red/amber/green fill **+** the numeric `n / max WP` label is always co-rendered — bar color never stands alone.
- Destructive buttons: red **+** isolated position/full-width row **+** distinct label text ("RUN AWAY", never an icon-only red button).
- Feature marks generally: PNG icon shape/silhouette is the primary signal; color is secondary reinforcement.

## Controls & Interaction

**Two control schemes, tap-to-move default (UX-01):**
- **Tap-to-move (default):** tap an orthogonally-adjacent, currently-seen (fog-revealed) square to step one square toward it. No tap-anywhere auto-path in v1 (per CONTEXT.md — auto-path complicates deterministic turn resolution and can spring traps/encounters unpredictably). Tapping a non-adjacent or unseen square is a no-op (optionally a subtle flash/shake, no error dialog).
- **D-pad (alternate):** the mockup's 3×2 arrow grid, functionally identical to tap-to-move (one step per press, same adjacency/collision rules) — selectable in Settings.
- Persist the choice as `mazeworld.controlScheme` ('tap'|'dpad') via `window.mzStorage`.

**Viewport pan/recenter:** the maze viewport supports free drag-pan (pointer down/move/up) independent of the player's logical position; `CENTRE` snaps the pan back to `{x:0,y:0}` (player-centered). Panning never moves the player — it's camera-only.

**Dice transparency (`diceMode` setting, signature feature):** `on tap` (default, mockup default) — each log/combat line's roll detail is hidden until tapped; `always` — roll detail is always visible inline; `never` — roll detail is never shown (narration text only). Applies uniformly to the Oracle log AND the combat log.

**Confirm-before-quit (UX-07):** gates (a) the Android hardware/gesture back button mid-run (already implemented behavior in `nativeChrome.js`, Phase 2 — this phase doesn't change that logic) and (b) the Sheet's `CUT LOSSES · ROLL ANOTHER` action, since both discard a live run. When ON (default): show a confirm dialog before executing — suggested copy: "Cut it loose? [character name] is still alive down there." with `CUT LOSSES` (destructive) / `KEEP GOING` (default-focused) buttons. When OFF: action executes immediately. `RUN AWAY` in combat is explicitly NOT gated by this setting (it's a normal in-run action with its own dice roll, not a run-ending action) — its mis-tap protection is purely the isolation/sizing/color treatment above.

**Fog-of-war:** always ON, not user-facing (per CONTEXT.md — the mockup's `fogOfWar` boolean prop is a design-tool toggle only, not a shipped setting).

## Accessibility Contract (UX-08)

- **Colorblind-safe:** see the per-instance list under Color above. Rule of thumb for every future addition in this phase: if a state is conveyed by color, it must ALSO be conveyed by an icon, shape, or text label that doesn't depend on color perception.
- **Rem-based text scaling:** S/M/L setting (`mazeworld.textSize`) drives one root multiplier affecting all four typography roles + the maze cell size together (see Typography). Never scale roles independently.
- **OS font-scale honoring:** respect the platform's accessibility text-scale setting, clamped to the same 0.85×–1.25× bound as the in-app S/M/L setting so extreme OS settings can't break the fixed-width pixel-art chrome (HUD numbers, tab bar, D-pad).
- **≥48dp touch targets:** see the 48dp Corrections table above (cross-referenced from UX-02, enforced as part of this accessibility contract too).
- **Motion:** the mockup's decorative keyframe animations (`mwflick` dice-reel flicker, `mwrise`/`mwfade` sheet transitions, `mwglow` player pulse, `mwtorch` torch flicker) are decorative-only and never the sole carrier of required information — no reduced-motion contract is mandated by UX-08, but keep these animations skippable/instant-legible (e.g. the roll reveal's `phase >= 4` check works whether or not the flicker plays).

## Safe Areas & Layout (UX-03)

- **Top HUD:** the mockup bakes in a fixed `padding-top:50px` sized for its iOS preview frame's notch — replace with `padding-top: calc(12px + env(safe-area-inset-top))` (or the equivalent for whatever container owns the top offset) so it adapts to the real device's status bar / cutout instead of a hardcoded value.
- **Bottom tab bar / controls:** the mockup's `padding-bottom:20px` on the outer app shell is similarly a fixed iOS home-indicator offset — replace with `padding-bottom: calc(8px + env(safe-area-inset-bottom))` on the tab bar and the maze bottom-control bar, for Android gesture-navigation.
- **Portrait lock:** already configured (Phase 2, `@capacitor/screen-orientation`) — this phase does not touch that; the layout above assumes portrait-only and does not need a landscape variant.
- **DPR-aware canvas:** extend the EXISTING `mazeworld.html` pattern (`<canvas id="maze">` + `ctx.setTransform(dpr,0,0,dpr,0,0)`, ~line 1330) — do NOT switch to the mockup's DOM div-grid rendering. Build the mockup's viewport FRAMING (pan transform, vignette box-shadow, fog overlay, MARKS/CENTRE chips, flash toast) as a DOM/CSS layer positioned around/over the canvas, with the canvas itself remaining the actual maze/grid/marks/player renderer at device DPI.
