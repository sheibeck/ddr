<threat_model>
## Trust Boundaries
| Boundary | Description |
|----------|-------------|
| touch/canvas input → engine action | Screen taps/drags are untrusted geometry resolved to validated move actions |
| build tooling → shipped bundle | Icons are committed source copied at build time (no runtime fetch) |

## STRIDE Threat Register
| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-04-13 | Tampering | tap resolving to an invalid/out-of-bounds move or bypassing applyAction | high | mitigate | resolveTapDirection returns a dir only for an adjacent+seen cell; the move flows through dispatch()->applyAction->engine/movement.js which re-validates walls/bounds; no client "reachable" shortcut mutates state directly (04-RESEARCH.md V5). |
| T-04-14 | Tampering | drift between draw() geometry and the tap hit-test (two transform copies) | medium | mitigate | Both read controls.js screenToCell + the single shared cs/pan/DPR object; no second geometry copy exists. |
| T-04-15 | Tampering | icon PNGs altered/missing at build | low | accept | Committed source, no runtime fetch; preloadIcons fail-opens so a missing icon never blocks boot. |
</threat_model>
