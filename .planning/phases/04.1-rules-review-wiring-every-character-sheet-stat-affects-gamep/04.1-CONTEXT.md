# Phase 04.1: Rules Review & Wiring — Context (Locked Decisions)

**Captured:** 2026-09-09 (via design Q&A with the user; supersedes a formal discuss-phase for this phase)
**Source:** 04.1-RESEARCH.md audit + user design decisions
**Domain:** Rules audit / wiring for the deterministic engine (`engine/*.js`) + content (`content/*.js`) + browser presentation (`src/browser/*.js`, `mazeworld.html`)

## End goal (user's own words)

> If you see information on your character sheet that reads like it impacts your gameplay, it should impact your gameplay in some fashion.

The audit found the engine is **far more wired than assumed** — only Intelligence is a true cosmetic orphan, phobias are 4/10 wired, and one dead-code bug silently disables two subclass abilities. This phase is ~80% "confirm, rename, and fix," ~20% new mechanics (bespoke phobias).

## Non-negotiable constraints (from CLAUDE.md — carry into every plan)

- **Fidelity rule:** the prototype's rules are canon; every fix is a *deliberate* rules change and must be logged in-code following the existing `// DELIBERATE RULES CHANGE (…)` comment precedent (`engine/movement.js:239-248`).
- **Engine purity/determinism:** all new resolution logic lives in `engine/*.js` as pure `(state, rng, events) → events` functions — never DOM code in `mazeworld.html`. No `Math.random()`; only the seeded rng. Preserve RNG consumption order where parity/determinism tests depend on it.
- **Do NOT rename state fields or event types** — `c.sp`, `c.wp`, `c.maxWP`, `c.rations`, event types (`spGained`/`healed`/`struck`/…). 9+ engine files + the parity/determinism/roundtrip suites + on-device save files key off these. Renames are **player-facing TEXT ONLY**.
- **Tone:** dark-but-family-friendly deadpan sarcasm for any new narration (`content/flavor.js` / `src/browser/eventNarration.js` voice).
- **No new deps/SDKs.**
- **Test gate:** `npm run test:quick` per task commit; `npm test` (full, currently 499/499) per wave/phase gate. `test/unit/formatEventsCoverage.test.js` fails the build if any new event type lacks narration — rely on it, don't route around it.

## Locked decisions

### TERM-01 — "skill points" → "experience points" (text-only)
Rename all player-facing "skill point(s)" strings to "experience points" (use "XP" where space is tight — HUD footer, kit rows). Sites: `mazeworld.html`, `content/flavor.js`, `content/epitaphs.js`, `src/browser/eventNarration.js`, `src/browser/viewModels.js` (`stats` label). State field stays `c.sp`.

### TERM-02 — "Win Potential"/"wp" → "Hit Points"/"hp" (text-only)
Rename the HERO-sheet label + flavor blurbs + event-narration unit + the **engine-generated store-row label** (`engine/economy.js:85` — a string embedded in serialized `state.store.stock[i].n`; update `test/unit/economy.test.js` fixtures in the same commit). **This also fixes a live bug:** the HUD already says "HP" while the sheet still says "Win Potential" — the app currently shows two names for one stat. State fields stay `c.wp`/`c.maxWP`.

### RULE-02 — Fix the `c.dr` dead-code bug (Sewing + Master of Arms)
`engine/movement.js:214-232` gates Thief **Sewing** (armor self-repair) AND the Fighter subclass **Master of Arms** repair bonus behind `c.dr > 0`, but `c.dr` is never set anywhere — dead code. Master of Arms' headline "+2 with every weapon" has **no implementation at all**. Fix both: set/replace the `c.dr` condition so Sewing's armor-patch fires, and implement the flat "+2 with every weapon" weapon-proficiency bonus for Master of Arms in `engine/derived.js` (`weaponDamage`/`toHit`). Log as a deliberate rules change. Add `test/unit/movement.test.js` coverage.

### RATION-01 — Sell rations directly (decouple from food/HP)  → **user chose Option A**
- Add **Rations** as its own store line item at a set gold price (its own resource).
- Food purchases (`STORE_EFFECTS.eatRation` / stock gen in `engine/economy.js:39-43,85`) become **pure HP healing** with NO ration side effect.
- Apply the same decoupling to the parallel dungeon-tile path `engine/encounters.js:256-263` (`findFood`) so the "any food = +1 ration" rule is removed in both places together.
- Surface ration changes explicitly in the UI (the current silent +1 was the core confusion). Keep the Cooking-skill beast-carcass ration path (`combat.js:345-354`) — that one is an intended, narrated foraging reward.
- Update `test/unit/economy.test.js` + `test/unit/encounters.test.js`.

### RULE-01 — Intelligence gets a self-contained mechanical read  → **user chose Option B**
Wire `c.intel` into a small, self-contained check now (no dependency on foes gaining spellcasting). Preferred hooks (planner picks the cleanest 1–2): an INT-scaled bonus to `openChest`'s lock roll (`encounters.js:106-113`) and/or a reduction of the Apprentice's spell-backfire chance (`magic.js`). Add the read in `engine/derived.js` as an exported helper so `viewModels.js` and the engine stay in sync (mirrors the `damageBracket`↔`weaponDamage` pattern). Add a unit test asserting a higher INT changes the outcome.

### PHOBIA-01 — Bespoke effect per phobia; new systems allowed  → **user chose Option C (the ambitious path)**
Keep the 5 working type-matched phobias (Beasts/Walking Dead/Demons/Magical/Humans freeze on matching encounter). Give each of the **5 inert `t:null` phobias (Darkness, Death, Being trapped, Bodies of water, Heights) a distinct, flavor-matched effect**, adding new systems where needed. Every phobia effect must respect the existing **Hardiness "phobias halved"** 50%-mitigation pattern (`combat.js:193`) for consistency. Proposed per-phobia designs (planner to confirm against code; adjust cheapest real hook):

- **Darkness** — **user's explicit steer:** there are darkness effects "on tables" that currently do nothing. Wire a **real persistent darkness state**: while darkness persists it **shrinks the fog-of-war / sight radius** and the character **counts as `inDark`** (the engine already applies in-dark to-hit penalties; Night Vision already waives them). A Darkness-phobic character additionally **freezes/panics** when an encounter starts while in darkness. **Action for the planner:** locate the inert darkness table effects (content/encounter tables) and wire them into this darkness state — this connects an orphaned mechanic AND the phobia.
- **Death** — near-death panic: when a Death-phobic character's own HP drops below a threshold (e.g. ≤25% of maxHP), apply a fear penalty (to-hit penalty and/or a chance to lose the action to panic). A genuinely new low-HP trigger.
- **Being trapped** — fear penalty/freeze in enclosed situations: on entering a dead-end / one-way-door / gorge tile, or a locked-chest "trapped" moment. Reuse existing tile/climb-check math.
- **Heights** — climb/leap penalty (or freeze) on climb/leap/gorge tiles (`movement.js` climb math already exists).
- **Bodies of water** — the maze has no water tiles today. Planner to find the cheapest **real** hook (a water-themed encounter/affliction trigger, or a minimal rare water hazard). This is the one allowed to fall back to flavor-only **only if** no cheap real hook exists — but the user preference is a real effect where feasible.
- Re-rolled phobias (`encounters.js` `newPhobia` / affliction re-roll) draw from the same catalog, so all 10 must behave once wired.
- Extend `test/unit/combat.test.js` (and movement/darkness tests as needed) so each phobia's documented effect is asserted.

### SCROLL — Deferred  → **user chose Option A (defer entirely)**
Leave the current "undifferentiated count, random spell on read" scroll model as-is. A type-system rework (`c.scrolls` int→array, 5+ files, save-shape change) is **OUT OF SCOPE** for this phase — revisit in a later phase if desired.

## Scope fence

**IN SCOPE:** TERM-01, TERM-02, RULE-01 (Intelligence, self-contained), RULE-02 (c.dr bug + Master of Arms +2), RATION-01 (sell rations directly), PHOBIA-01 (bespoke per-phobia incl. the darkness-state wiring).

**OUT OF SCOPE (deferred):**

- Renaming any engine **state field or event-type identifier** (save-migration class change).
- **Temperament / Motive** mechanical effects — these sheet lines are pure flavor with zero engine reads (QUIRK-01 in research). Explicitly **flavor-only for this phase**; candidate for a future pass. (Phobia is the quirk-line element getting teeth this phase.)
- Foe offensive spellcasting (would be required for symmetric INT spell-resistance — not this phase).

## Success criteria (what must be TRUE at phase end)

1. No player-facing screen shows "skill points" or "Win Potential"/"wp" for HP — the HUD and HERO sheet agree ("HP" / "experience"/"XP").
2. Buying food heals HP only; rations are a distinct purchasable/foraged resource, and any ration change is shown to the player.
3. Thief Sewing repairs armor in play, and Master of Arms confers its "+2 with every weapon" bonus — both provable by a test.
4. Intelligence measurably changes at least one gameplay outcome (a higher INT yields a different result), provable by a test.
5. All 10 phobias produce a documented mechanical effect when triggered (the 5 formerly-inert `t:null` ones now bite), Hardiness still halves them, and the Darkness phobia is backed by a real persistent darkness/fog-of-war state that also gives the previously-inert darkness table effects meaning.
6. `npm test` full suite green (determinism/parity/roundtrip intact); every new event type has narration coverage.
