# Phase 04.1 Plan 06: Death/Heights/Bodies-of-Water/Being-Trapped Phobia Effects Summary

**Wired the final 4 formerly-inert phobias to bespoke, Hardiness-halved mechanical effects — Death panics near-death via the existing frozen/shookOffFrozen seam, Heights and Bodies of water add a deterministic penalty to the climb/leap roll comparison, and Being trapped fires a debounced dead-end-entry panic — completing all 10 catalog phobias; `npm test` 535/535 green.**

## Accomplishments

- **Death — near-death combat panic (Task 1).** `engine/combat.js`'s `startCombat` phobia-freeze condition, already generalized once for Darkness in 04.1-05, was generalized a third time: `c.phobia === "Death" && c.wp <= c.maxWP * 0.25` (documented `DEATH_PANIC_THRESHOLD`) is now a third OR-chain operand alongside the type-matched and Darkness checks, reusing the identical `state.combat.frozen`/`shookOffFrozen` seam and the single existing Hardiness `rng.d(2)` mitigation roll. All three operands stay provably mutually exclusive per character (every PHOBIAS catalog entry carries exactly one `phobia` name), so no character can double-trigger the freeze or double-roll Hardiness, and the new roll only ever fires for a Death-phobic character who is actually near death and has Hardiness — never during chargen, never for anyone else. Reused the existing `phobiaFrozen` narration (no new event needed).
- **Heights and Bodies of water — movement roll penalties (Task 2).** In `engine/movement.js`'s climb/gorge block, a Heights-phobic character's climb roll `r` and a Bodies-of-water-phobic character's gorge/crevice-leap roll `r` each get a documented `+2` deterministic penalty added directly to the comparison (`HEIGHTS_PHOBIA_PENALTY`/`WATER_PHOBIA_PENALTY`), Hardiness-halved to `+1` via `Math.round(2/2)`. Neither path adds a new rng draw — the penalty only shifts the pass/fail threshold of an *existing* roll — so parity/determinism stay trivially safe by construction. Each phobic attempt pushes a `heightsFear`/`waterFear` fear event (new `EVENT_NARRATION` entries, deadpan tone).
- **Being trapped — debounced dead-end panic (Task 2).** A genuine ENTRY into a dead-end tile (`isDeadEnd(f,x,y)`: exactly one, or zero, non-wall orthogonal neighbor) by a Being-trapped-phobic character triggers a deterministic 4-wp panic (`TRAPPED_PHOBIA_PANIC`, Hardiness-halved to 2, clamped to leave at least 1 wp), pushing a `trappedPanic` event. Per the plan's explicit DEBOUNCE warning, this is one-shot per tile via a marker on the TILE OBJECT ITSELF (`there.trapPanicked`), set the first time the panic fires there — never a bump/blocked no-op, never a new chargen field. A regression test proves a second consecutive entry into the identical dead-end tile does not re-fire it.
- **13 new tests** (5 in `combat.test.js`, 8 in `movement.test.js`) directly proving: the Death panic fires at/below the threshold and not above it; a non-Death phobia near death never freezes; Hardiness's 50% mitigation both succeeds and fails; Heights/Bodies-of-water borderline rolls flip pass↔fail purely from the phobia flag with an identical rng sequence; Hardiness halves each penalty enough to turn the same borderline roll back into a pass; Being-trapped panics on first dead-end entry, does NOT re-panic on a debounced second entry, never panics for an unrelated phobia, and Hardiness halves the loss.
- **Full suite: 522/522 → 535/535 green**, including parity/determinism/roundtrip — verified with zero test-file changes needed in `test/parity/*` (see the parity-safety analysis below).
- **All 10 catalog phobias now produce a documented mechanical effect**: the 5 original type-matched freezes (Beasts/Walking Dead/Demons/Magical/Humans), Darkness (04.1-05's persistent-darkness freeze), and these 4 (Death/Heights/Bodies of water/Being trapped). Re-rolled phobias (`newPhobia`/affliction catch) draw from the same `PHOBIAS` catalog, so every possible roll behaves.

## Decisions Made

- **Death threshold and hook:** `c.wp <= c.maxWP * 0.25`, checked only at `startCombat` (encounter start), never mid-fight — matches the plan's "~25% of maxHP" language and the existing freeze-check's single-evaluation-point design.
- **Heights/Water penalty magnitude and application point:** `+2` (Hardiness-halved to `+1`) added to the roll `r` itself, before the `r <= tbl.success` / `r > need` comparisons — the plan's own explicit design constraint ("modifies the COMPARISON only, adding NO rng draw").
- **Being-trapped hook choice:** dead-end-tile ENTRY only, not the one-way-door block. The plan allowed "and/or"; the one-way-door block is itself a no-op (no state change, early `return`) and re-firing it on every repeated bump was exactly the failure mode the plan's DEBOUNCE warning called out. Dead-end entry is a genuine state-changing move, so a tile-level debounce marker cleanly and testably satisfies the "second consecutive attempt does NOT re-apply it" regression requirement.
- **Debounce marker placement:** on the tile object (`there.trapPanicked`), not a new chargen field. This was a deliberate departure from 04.1-05's `c.darkFor` precedent (a genuine ongoing per-character condition, correctly a character field) — a per-tile one-shot marker's natural scope is the tile, and keeping it there avoided the 5-file parity-carve-out cost `c.darkFor` required, since a tile marker can only ever exist on a tile a Being-trapped-phobic character has actually panicked on.
- **No content/flavor.js changes.** The plan explicitly marked situational-tag additions to the `PHOBIAS` catalog as optional ("keep the EFFECT logic in the engine; content is data only"); the engine already branches on `c.phobia === "<name>"` directly (matching 04.1-05's Darkness pattern exactly), so no catalog change was needed or made.

## Parity-Safety Analysis (why no carve-out was needed)

Before implementing, I verified directly (via `newRun(seed)` for every fixed-seed character every parity fixture uses) that none of this plan's new triggers can fire during an existing parity/determinism/roundtrip fixture's fixed action script:

- **Death** (`c.wp <= 0.25*maxWP` at encounter start): every parity fixture's `startCombat` call is the FIRST action against a freshly-rolled character (`wp === maxWP`), so the near-death condition can never be true regardless of phobia. Confirmed none of the combat-parity fixture's 4 seeds (3/14/17/303) roll "Death" anyway.
- **Heights/Bodies of water** (climb/gorge roll penalty): only fire on a `climb`/`gorge` feature tile inside `move()`. The movement-parity fixture's action script is a feature-avoiding path (its own header comment: "avoid ... every rng-dependent climb/gorge roll") and its seed-256 character's phobia is "Vampires and the undead" (type-matched, pre-existing behavior) — not Heights or Bodies of water. No other parity fixture calls `move()` with a climb/gorge tile.
- **Being trapped** (dead-end-tile entry): only fires inside `move()`. The movement-parity fixture is the only parity fixture that calls `move()`, and its character's phobia is "Vampires and the undead" (confirmed via direct `newRun(256)` inspection), not "Being trapped" — the mechanic can never fire regardless of the maze's actual tile layout. Combat-parity's seed 17 DOES roll "Being trapped" and seed 303 rolls "Heights", but neither of those fixture scenarios (`flee`/`parley`) contains a single `move` action — only `startCombat`/`flee`/`parley` — so the movement-only mechanics never engage.

This is why `npm test` passed at 535/535 with zero changes to any `test/parity/*` file.
