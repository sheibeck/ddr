Bolt the Web Audio backend onto `src/browser/sfx.js`: one decode of all 30 clips at unlock, a fresh source node per play so simultaneous events overlap, a bounded voice pool, and the fail-open degradation that keeps a missing or still-decoding clip from ever throwing.

    Append to `src/browser/sfx.js`, keeping the pure section above untouched.

    **Backend seam.** Define a small internal backend interface with exactly five methods, and document it in a comment as the whole surface the player needs so a fake is trivial:
    - `open()` — constructs/resumes the audio device, resolving to an opaque handle, or to `null` when audio is unavailable.
    - `load(handle, clipId)` — fetches and decodes one clip, resolving to an opaque buffer or to `null` on any failure.
    - `start(handle, buffer)` — starts one voice immediately and returns an opaque voice handle, or `null`.
    - `stop(voice)` — stops one in-flight voice.
    - `close(handle)` — tears the device down.

    Define `DEFAULT_BACKEND` implementing that interface over Web Audio: `open()` constructs an `AudioContext` (using the standard constructor with the webkit-prefixed fallback) and awaits `resume()`; `load()` does a same-origin RELATIVE request for `./sfx/<clipId>.mp3` and passes the bytes to `decodeAudioData`; `start()` creates a fresh buffer-source node per play, connects it through a single shared master gain node into the destination, and starts it at the context's current time with no lead-in or lookahead; `stop()` calls the node's stop; `close()` closes the context. Every method is individually wrapped so a throw becomes a `null` return, never a propagated exception. The clip path must be relative — no absolute URL, no host, no scheme — because the clips live in the bundled `www/sfx/` copy and AUD-06 forbids any network reach.

    Define `resolveBackend()` returning `globalThis.__mzSfxBackendOverride?.() ?? DEFAULT_BACKEND`, read at call time so a test can swap it per test. Shipped code never assigns the global.

    **State.** Module-level: the current settings mirror (default treated as sound-on-unknown until `applySfxSettings` runs, but with no device opened until unlock), the open handle (`null` until unlock), a `Map` of clipId to decoded buffer, a flag for "unlock in progress", and a FIFO array of live voices.

    **`VOICE_CAP`** — an exported constant, value 8, commented as CONTEXT's polyphony cap: full overlap is required by AUD-04, but an unbounded voice count is a mid-range-phone hazard.

    **`unlockSfx()`** — exported, async, idempotent, never throws. Bails immediately when the Sound setting is off (this is the guard that makes "no audio device is opened" literally true), when a handle already exists, or when an unlock is already in flight. Otherwise calls `backend.open()`; on a `null` handle it gives up silently and leaves the module in its resting state so a later gesture can retry. On success it stores the handle and kicks `backend.load()` for ALL 30 clip ids in parallel, storing each resolved buffer in the cache as it lands and storing nothing for a `null`. It does NOT await the loads — decode is off the critical path.

    **`playClips(clipIds)`** — internal. Returns immediately when there is no handle, when the Sound setting is off, or when the list is empty — touching no state in any of those cases. For each id IN THE ORDER RECEIVED: look up the decoded buffer; when the buffer is absent (still decoding, or its file was missing or failed to decode) DROP that one clip and continue with the rest — never queue it, never retry it, never throw. Otherwise `backend.start()`; when it returns a voice, push it onto the FIFO, and while the FIFO length exceeds `VOICE_CAP` shift the oldest voice off and `backend.stop()` it. Comment the two pinned rules in place: a still-decoding clip is dropped rather than queued (a late sound is worse than no sound), and the 9th voice stops the oldest rather than being refused.

    **`playForDispatch(actionType, events, ctx)`** — exported. Calls `clipsForDispatch(actionType, events, ctx)` and hands the result to `playClips()`. Returns `undefined` always. Wrapped so nothing it does can throw into `dispatchWithNarration`.

    **`playUiTap()`** — exported. Plays the `uiTap` group through the same variation and `playClips()` path. Returns `undefined`, never throws.

    **`stopAllSfx()`** — exported. Stops every live voice and empties the FIFO. Never throws.

    **`applySfxSettings(settings)`** — exported. Stores the settings mirror. On a transition to sound OFF it calls `stopAllSfx()`, then `backend.close()` on the handle, then clears the handle and the buffer cache — the pinned answer to the toggle-boundary edge: in-flight voices STOP IMMEDIATELY rather than being allowed to finish. On a transition to sound ON it does NOT open anything; the next `unlockSfx()` call (driven by the next user gesture) opens and re-decodes. Comment that this is what keeps "flip Sound on before any gesture" silent-but-errorless.

    Nothing in this task may touch the pure section's exports, add an import, introduce a timer or delay constant, or consult a pseudo-random source.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| bundled `www/sfx/` -> decode path | Untrusted-shaped bytes cross into `decodeAudioData`; a corrupt or truncated file must not crash the app. |
| WebView audio device -> app | The platform may refuse to open a context, refuse to resume, or evict it; every one of those is a normal state, not an error. |
| `globalThis.__mzSfxBackendOverride` -> player | A test-only hook that, if ever set by shipped code, would let arbitrary code intercept playback. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-56-08 | Denial of Service | voice pool | high | mitigate | Hard `VOICE_CAP` of 8 with oldest-dropped eviction; a burst of dispatches cannot grow the node count without bound on a mid-range phone. Asserted by the cap-boundary test with a teeth case. |
| T-56-09 | Denial of Service | decode path | medium | mitigate | All decodes fire once at unlock and are never retried; a clip that fails or never resolves is dropped permanently rather than re-fetched per play, so a corrupt file cannot become a per-action fetch loop. |
| T-56-10 | Tampering | `__mzSfxBackendOverride` | medium | mitigate | Shipped code only ever READS the global; a grep asserts there is no assignment, and the BRIDGE entry documents it as test-only — the same posture `__mzHapticsImportOverride` already ships under. |
| T-56-11 | Information Disclosure | clip fetch path | high | mitigate | Clips load by same-origin RELATIVE path out of the bundle; a grep asserts no absolute URL scheme appears in the module, so the offline gate cannot regress into a network call. |
| T-56-12 | Spoofing | `decodeAudioData` on bundled bytes | low | accept | The only bytes reaching the decoder are the 30 clips shipped inside the signed AAB; there is no user-supplied or remote audio path to spoof. |
| T-56-SC | Tampering | npm/pip/cargo installs | high | accept | This phase installs no packages — `package.json` is not modified. No legitimacy checkpoint is required because there is no install task. |
