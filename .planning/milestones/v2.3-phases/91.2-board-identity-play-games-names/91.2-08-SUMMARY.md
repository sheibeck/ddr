## Behaviour

- **Seam (D-02, T-91.2-28).** `playIdentity()` builds `createPlayIdentity()` on native and `createFakePlayIdentity()` otherwise, once. Building calls no plugin method; the SDK starts only when boardSync's Compete-gated session asks. A source test pins that the seam builder calls none of init / status / signIn / serverAuthCode.
- **Sessions.** `onSession: (info) => account?.sessionChanged(info)`; the account controller still reads `boardIdentity()` and `boardSync` as before. The `onAcked` -> `account.boardAcked()` wiring was already in place and is unchanged. On resume (visible) the first `visibilitychange` listener runs `boardSync.session()` (quiet when signed out or Compete OFF); `online` still forces a flush. `boardSync.boot({ history })` still runs before any session at launch.
- **SIGN IN (D-03).** Dropdown block: stops propagation (the ☰ stays open), calls `account.signInTap()`, raises no select sound. Title sheet: `onSignIn: () => account.signInTap()`. No `reroll` / `ensureHandle` text is left in the shell.
- **Dev row (D-10, T-91.2-29/30).** Long-press the version label (1.2 s) reveals both dev rows. PLAY GAMES PROBE disables itself while running, runs `runPgsProbe({ playIdentity: playIdentity(), fetchFn })` (native fetch on Android, `boardFetch` in the dev loop), prints the pretty JSON in `#mw-dev-pgs-out` and logs one `[pgs-probe] <compact json>` line (`adb logcat | grep pgs-probe`). The fake sign-in toggle (browser dev loop only; hidden on native) flips `setSignedIn` and calls `boardSync.session()`; its label reads "Fake sign-in: ON/OFF".
- **Handles removed (D-10/D-11).** `grep -rln "handles.js" src content tools mazeworld.html` prints nothing; `runDoc.js`'s transition-only `legacyHandleUpdateCommit` and `LEGACY_HANDLE_PATTERN` stay.
