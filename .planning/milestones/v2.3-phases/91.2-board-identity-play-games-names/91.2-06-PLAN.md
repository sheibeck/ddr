<interfaces>
runQueue (additions):
- a `submitRun` result with reason "signin" holds the queue: the entry stays first, its attempts, the record's failures and retryAt are untouched, and flush resolves `{ ok: false, reason: "signin", sent, dropped }`.
- `requeue(list, { versionOf, version })` → `{ ok: true, queued, skipped }` | `{ ok: false, reason: "off" }`: Compete-gated, no network, one persist; each valid summary whose hash is in `settled` and not already an entry is removed from `settled` and queued with `versionOf(hash)` when that returns a valid version string, else `version`.

boardSync (additions; options gain `onSession`):
- `session()` → info; `signIn()` → info. info = frozen `{ state: "signedIn" | "signedOut" | "unavailable" | "offline" | "error" | "off", name: string | null }` (ok → signedIn with the name; reason signin → signedOut; unavailable → unavailable; offline → offline; server or refused → error; off → off). Both call `onSession(info)`; on signedIn they run the D-05 re-post (once) and then `flush({ force: true })`.
- `flush()` additionally calls `onSession({ state: "signedOut", name: null })` when the queue answers reason "signin".
- `boot({ history })`: today's steps, then (Compete ON) `session()` instead of the plain flush.
- Re-post marker: `ddr.boardRepost.v1` = `{ v: 1, done: true, count }`.
- `client` must now also offer `ownRuns(uid)` (src/browser/boardClient.js already does).
</interfaces>
