<objective>
Build the trusted name writer (D-01): a zero-dependency Cloud Function that turns a verified Play Games link into a `names/{uid}` record, stamps that name onto every run of the player (their 2.2.0 @handle runs included, D-04 / BOARD-32), adopts an anonymous uid's runs when linking could not keep the uid, and releases the record on erase. Add its browser client, the D-08 name matcher, the moderation commands, and a dry-run-by-default deploy script. Nothing is deployed here.

Purpose: BOARD-31's "verified, not trusted from the client": rules can only compare a run's handle with a document a trusted writer controls, and on Blaze that writer is this function.
Output: `functions/board-names/` (core, HTTP entry, package.json), `src/browser/nameClient.js`, `src/browser/nameFilter.js`, `tools/board-names/deploy.mjs`, boards-admin `names` / `name-override` / `name-clear`, and their tests.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client → boardName function | an untrusted caller presents an ID token and optional adopt token / auth code |
| function → Google (Identity Toolkit, OAuth, Games API) | Google validates tokens and supplies the name |
| function → Firestore (service account) | IAM bypasses the rules; the function must enforce ownership itself |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-91.2-04 | Spoofing | claim | critical | mitigate | the caller is whoever Google's accounts:lookup says the token belongs to; the name comes from providerUserInfo (or players/me with a playerId match), never the request body |
| T-91.2-05 | Elevation of privilege | adopt | high | mitigate | adopt only from a provider-less account whose own valid token the caller presents, never the caller's own uid; runs move only to the caller |
| T-91.2-06 | Information disclosure | responses and logs | high | mitigate | error codes only; no token, secret or upstream body in any response; the client secret only in Secret Manager |
| T-91.2-07 | Denial of service / cost | function | medium | mitigate | max 3 instances, 60 s timeout, names written only on change, stamping skips equal handles; budget alert in 91.2-10 |
| T-91.2-08 | Tampering | offensive gamer names | medium | mitigate | D-08 client mask (91.2-07) plus admin override and delete-run |
</threat_model>
