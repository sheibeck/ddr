## How it behaves

- **claim**: `accounts:lookup` on the caller's own ID token (401 for INVALID_ID_TOKEN, TOKEN_EXPIRED, USER_NOT_FOUND, USER_DISABLED; 502 for 5xx or network); no `playgames.google.com` provider is 403 NOT_LINKED with zero writes; the name is the sanitized providerUserInfo displayName (or `nameOverrides/{uid}`, reported `overridden`); `names/{uid}` is PATCHed only when it changed (fields `name`, `updatedAt`, no mask); then adopt (if asked), then stamp. Stamp pages runs by `uid ==` (300 per page, `__name__` cursor) and commits only the docs whose handle differs, `updateMask ["handle"]`, `currentDocument.exists true`, at most 500 writes per commit.
- **adopt**: only from a provider-less uid whose own valid token is presented and that is not the caller; otherwise 403 ADOPT_REFUSED before any write. Runs move to `<caller>_<hash>` with `uid`, `handle` and `deepKey` (recomputed) replaced and every other field (createdAt included) copied; the source is deleted in the same commit, 200 runs (400 writes) per commit; a re-run is idempotent.
- **games source** (`NAME_SOURCE=games`): no code is 409 NEEDS_GAMES_CODE; with a code it posts the form-encoded token exchange (empty `redirect_uri`, marked [ASSUMED] in a comment), calls `players/me` and requires `playerId == rawId` (else 403 GAMES_MISMATCH). The secret never appears in a response.
- **release**: deletes `names/{uid}` for any valid token (no Play Games provider needed); `nameOverrides` is untouched.
- **index.js**: OPTIONS 204 with the four CORS headers, other non-POST 405, Bearer (case-insensitive) else 401, JSON/string/Buffer body else 400, op routing, a thrown core becomes 500 INTERNAL. Loading the module makes no network call.
- **nameClient**: network or timeout offline; 401 auth; 409 NEEDS_GAMES_CODE needsCode; 400/403/422 refused with the server's code (only if it looks like a code); 429/5xx server; no fetch or non-https unavailable; a 200 whose name fails sanitizing server. No token ever appears in a result (tested).
- **nameFilter**: token rule (including multi-word terms, allowlisted tokens exempt) plus an embedded rule on the letters-only form for terms of 4+ letters, allowlist-aware, accent and case blind. `nameFlagged(name, { banned, allowlist })` takes optional lists (used by tests with made-up words).
- **deploy.mjs**: `node tools/board-names/deploy.mjs` prints the gcloud deploy line and the expected URL (equals `BOARD_NAME_FN.url`), exit 0; `--setup` adds the API enables, service account and `roles/datastore.user` binding; `--name-source games --pgs-client-id <id>` adds the env var and `--set-secrets` and prints the Secret Manager steps (file outside the repo); a secret flag is a usage error (exit 2, value never echoed); commands run only with `--yes`, stopping at the first failure (exit 1).
- **boards-admin**: `names [--flagged] [--json]` (paged; flag evaluated on the effective name, override shown), `name-override <uid> <text> [--yes]` (dry run prints current name, sanitized override, run count; `--yes` writes `nameOverrides/{uid}` and `names/{uid}` then restamps via `createBoardNameCore(...).stamp`), `name-clear <uid> [--yes]`; usage names all three and says `delete-run` hides a run.

## Deviations from Plan

None to scope. Judgement calls the next plans should know:

1. **Invalid auth code maps to 409 NEEDS_GAMES_CODE.** The contract lists no code for a spent or rejected code at the token exchange; a fresh code is exactly what the client should send, so 400/401 from the OAuth endpoint answers NEEDS_GAMES_CODE (other failures 502). 91.2-05 should cap its retry at once.
2. **The function sends no `X-Goog-User-Project`.** The metadata-server token already belongs to the project; `adminHeaders` stays available for the admin tool, which passes the gcloud user-project header.
3. **Embedded-term rule is blunt by design (CONTEXT, D-08).** A real name that hides a 4+ letter safety-list term inside it (a place name or a common word) is masked; the admin override is the cure. Not changed here.
4. **`name-override` validates before authenticating** (empty-after-cleaning text is exit 2 with no network), like the other commands' positional checks.

## Notes for 91.2-03 (the fake board server)

The core writes with the admin token through `:commit` (stamp: handle-only patches with `currentDocument.exists true`; adopt: update + delete) and through single-document PATCH/DELETE on `names/{uid}`, and reads `nameOverrides/{uid}` and `names/{uid}` by GET and runs by `:runQuery` (`uid ==`, `__name__` order, `startAt` by reference). The current fake's commit-based writes are owner-gated even for `FAKE_ADMIN_TOKEN` (see the comment in `createAdminApi`), so the fake needs an admin bypass on `:commit` for the function to run against it; `test/unit/harness/boardNameStub.js` shows the exact request shapes.
