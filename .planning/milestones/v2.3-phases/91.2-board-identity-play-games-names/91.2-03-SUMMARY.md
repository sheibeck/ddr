## What the fake does now

- **Identity.** `accounts:signInWithIdp` takes fake codes `fake:<pid>:<name>:<n>` (single use). No idToken: creates a linked account (`isNewUser` true) or signs in to the linked uid (false). With an anonymous idToken: links and keeps the uid; `linkKeepsUid: false` returns a new uid (G3). The player linked to another uid answers `FEDERATED_USER_ID_ALREADY_LINKED` as a 200 `errorMessage` with `returnIdpCredential` (no tokens), else a 400. Reused or non-fake code: `INVALID_IDP_RESPONSE`; `playGamesEnabled: false`: `OPERATION_NOT_ALLOWED` (G4); a re-sign-in refreshes the provider name unless `refreshProviderName: false` (G2). `accounts:lookup` returns `providerUserInfo`; `accounts:update` unlinks (`deleteProvider`) or changes only the top-level `displayName` (`linkProviderUserInfo` is `ADMIN_ONLY_OPERATION`); `accounts:delete` frees the player. The account store is a map of records; `users()` output is unchanged.
- **Names.** `names/{uid}` and `nameOverrides/{uid}` answer only the admin token (GET 200/404, PATCH replaces or masks-merges, DELETE, collection GET list, admin `:runQuery`); every client or unauthenticated read, write, list, query or `:commit` is 403. Inspectors: `names()`, `overrides()`, `providers(uid)`, `setName`, `setOverride` (all frozen).
- **Admin commit.** Updates with or without `updateMask`, deletes and creates over runs, `currentDocument.exists` preconditions, atomic, 500-write ceiling, no client rule (the adopt shape of 91.2-02 works). Admin `:runQuery` over runs supports `uid ==`, `__name__` order and the `startAt` cursor with no client limit.
- **boardName.** At the exact `BOARD_NAME_FN.url` (path only; no API-key check; CORS on every answer; OPTIONS 204; other methods 405), with the HTTP handler's checks (Bearer, body, op, 8192-char fields) and the core's decisions. `nameSource: "games"` answers `NEEDS_GAMES_CODE` / `GAMES_MISMATCH` from fake codes; the fake also serves `oauth2.googleapis.com/token` and `games.googleapis.com/.../players/me` so the real core can run in games mode against it.

## The contract test

Each of 27 scenarios (first claim, repeat claim, no-write repeat, renamed provider, anonymous, invalid token, override, blank override, whitespace name, sanitizing, 64-unit cut with a surrogate pair, adopt of 3 runs, adopt of 301 runs across the core's two query pages and two commits, malformed hash skipped, adopt refused for own token / linked source / invalid source, release for linked, anonymous and invalid, and seven games-source cases) runs on four fresh identically-seeded fakes: (A) the real `createBoardNameCore` with `fetchFn` = the fake and `FAKE_ADMIN_TOKEN`; (B) a raw POST to the fake endpoint; (C) the fake endpoint through `createNameClient`; (D) the real `createHandler` over the core through `createNameClient`. A vs B must match status, body and the whole stored state (names with timestamps, overrides, every run document); C and D must give the client the same result and state. Fourteen more cases compare the HTTP surface (OPTIONS, 405, 401, 400 variants, lower-case Bearer, oversized fields, name-in-body ignored) with the real handler. A deliberate mutation of the emulation's stamp rule made 5 contract tests fail, so the guard bites.

## The probe

`runPgsProbe({ playIdentity, fetchFn, config, playConfig, now })` resolves a frozen `{ v: 1, at, steps, gates }`. Steps: init-status (A6), idp-sign-in (G4: a network failure is "check", a server answer is pass/fail), claims (A3: "skip" when the token is not a JWT), lookup (G1: "check" when the provider name equals the local name, "fail" when missing or different), tamper (A4: rename the top-level name, forged `linkProviderUserInfo` must be refused, provider name must not move, then the top-level name is restored or cleared), second-link (G3: a throwaway anonymous account must get ALREADY_LINKED in either its 200 or 400 form), cleanup (always; deletes the throwaway and only a Play Games account the probe created; a pre-existing account survives). Signed-out with no sign-in skips every network step. The report holds codes, booleans and 6-character uid prefixes; a test scans it for every token and code the fake minted.
