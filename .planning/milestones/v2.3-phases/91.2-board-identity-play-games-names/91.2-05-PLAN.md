`createIdentity(opts)` opts: `{ storage, fetchFn, config = FIREBASE_CONFIG, playConfig = PLAY_GAMES_CONFIG, playIdentity, nameClient, competeOn, now = Date.now, timeoutMs, setTimer, clearTimer, AbortCtl }`. `nameClient` defaults to `createNameClient({ fetchFn, ...timed opts })` (src/browser/nameClient.js, BOARD_NAME_FN).

Returns frozen:
- `snapshot()` → frozen `{ uid, name, linked, playerId }` (local, no network).
- `getToken({ explicit })` → `{ ok: true, uid, idToken }` | `{ ok: false, reason }` (anonymous sign-up when there is no uid; the bug-report path; unchanged semantics minus the handle).
- `forceRefresh({ explicit })` → same shape.
- `boardSession({ interactive = false })` → `{ ok: true, uid, idToken, name }` | `{ ok: false, reason }`; reason in IDENTITY_REASONS = `["off", "offline", "server", "refused", "unavailable", "signin"]`. Compete-gated always (never explicit); single-flight.
- `signIn()` → `boardSession({ interactive: true })`.
- `refreshName()` → `{ ok: true, name }` | `{ ok: false, reason }` (claim again; used after a refused create).
- `deleteAccount()` → Compete-gated; release the name through the function (best effort), then accounts:delete, then drop → `{ ok: true, deleted }` | `{ ok: false, reason }`.
- `drop()`.

Record (`ddr.identity.v2`, JSON): `{ v: 2, uid, refreshToken, idToken, expiresAtMs, linked, playerId, name, overridden, adoptFrom: { uid, refreshToken } | null }`. `LEGACY_IDENTITY_KEY = "ddr.identity.v1"`.

signInWithIdp request: POST `${IDENTITY_BASE}/accounts:signInWithIdp?key=<apiKey>` with `{ requestUri: "http://localhost", postBody: "code=<encodeURIComponent(code)>&providerId=playgames.google.com", returnSecureToken: true, returnIdpCredential: true, idToken? }`. `parseIdpSignIn(json, nowMs)` → `{ uid, idToken, refreshToken, expiresAtMs }` | `{ alreadyLinked: true }` (errorMessage FEDERATED_USER_ID_ALREADY_LINKED, or a 400 with that message, handled by the caller) | null.

`boardWrites.submitRun(summary, { version })` → `{ ok: true, status: "created" | "exists", id }` | `{ ok: false, reason }`; WRITE_REASONS gains "signin".

`makeBoardRig({ now, fakeOpts, play = {}, competeOn = () => true, storage })` (test/unit/harness/boardHarness.js) → `{ fake, play, storage, identity, config, playConfig }`: `createFakeBoardFetch` (final mode unless fakeOpts says otherwise), `createFakePlayIdentity(play)`, an in-memory storage map, and `createIdentity` wired to them with a test playConfig whose webClientId passes playGamesConfigured.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| device → Identity Toolkit | the client relays a server auth code; Google validates it |
| device storage → identity | the stored record (uid, tokens, name) is tamperable on a rooted device |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-91.2-17 | Spoofing | a tampered stored name | high | mitigate | the rules compare the handle with names/{uid}; a wrong local name is simply refused and re-claimed |
| T-91.2-18 | Elevation of privilege | adopting another player's runs | high | mitigate | the client only offers its own anonymous account's token; an account switch drops the session without adopting; the function refuses linked sources |
| T-91.2-19 | Information disclosure | tokens in results or logs | high | mitigate | reason ids only; no console calls; tests assert it |
| T-91.2-20 | Replay | reused server auth codes | medium | mitigate | each code is used once, immediately; retries fetch a fresh one |
| T-91.2-21 | Denial of service | rename relink loop | low | mitigate | one unlink-relink attempt per launch per target name |
</threat_model>
