ITEM-02, persistence: the effect-source link survives save, load and relaunch, old saves load tolerantly (linked to the matching worn item or ended quietly), Joiner sheets get the same treatment, and the new field is proven carved out of every parity compare.

Implements these CONTEXT decisions (88-CONTEXT.md):
- "Scope of the effect-source link": "the slot ... and the item, on the timer record itself, so it survives save, load and relaunch. New serialized fields are carved out of all three *Comparable() functions."
- "When an effect ends": "One mechanism: a single engine helper ends the effects linked to a slot, called from every gear-change path, plus one load-time reconciliation." This plan is that one reconciliation; it reuses 88-01's helper in quiet mode.
- "Old saves: on load, a live item effect with no recorded source is linked to the matching worn item if one is there; otherwise it ends quietly (tolerant load, no event)."
- "Joiners: covered by design ... The link and its end helper work on any character sheet (hero or Joiner) and are pinned on a Joiner sheet."
- "The Crystal Staff is linked too (user, 2026-09-30, after planning) ... The weapon slot joins the source slots" (88-01 links it in play; this plan reconciles it on load: a live Crystal Staff record links to a wielded Crystal Staff or ends quietly).
- Gates: "Greenfield: no dual code paths; old saves tolerant-load only."

Claude's discretion used: "ends quietly" means the same spent-use rule as a live early end (via endEffectEarly: a record with a cooldown becomes a cooldown of left + cd; the Crystal Staff's record, which has none, is removed with its charge left spent), so a load never hands an item back sooner than play would. The reconciliation runs after `reconcileWorn` in both load chains (and after sanitizeStaff, which repairs a stale c.staff/c.weapon pair), so a legacy save whose worn map is built at load still links, and a staff the load un-wields ends its effect.

Carve-out: the only new serialized field (`src`) rides inside `c.timers`, which `stripTimersField` already removes in all three comparable chains; this plan pins that with a test and names the field in the harness doc comment (harness, not a hedge).

Purpose: ROADMAP Phase 88 success criterion 2 ("after saving, quitting and relaunching in the middle of an effect, the effect still knows its item and ends when the item comes off", and the Joiner half).
