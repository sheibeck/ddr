Implements these CONTEXT decisions (88-CONTEXT.md, "Scope of the effect-source link", "When an effect ends", "Edge cases"):
- "The record carries its source: the slot (cloak, jewelry1, jewelry2) and the item, on the timer record itself" (persistence across save/load is 88-02).
- "Linked effects: the 12 worn items that start a timed effect ... plus the Cloak of Regeneration's new 30-square window" (the Regeneration window arrives with 88-04 and links automatically through the same stamp).
- "The Crystal Staff is linked too (user, 2026-09-30, after planning): a Magic User wields it in the WEAPON slot, and using it starts an item:Crystal Staff party invisibility of d10+5 squares (PARTY_WIDE_ITEM_EFFECTS) ... The weapon slot joins the source slots: taking the staff out of the weapon slot (unwield, swap, drop, sell, destroyed) ends the party invisibility like every worn item, with the same spent-use cooldown and narration."
- "Not linked: potions ... and the Torch are used up on use ... so their effects run their course."
- "Any slot change ends it: anything that empties the source slot or puts another item there: take off (unequipSlot), swap (equipItem / wearItem replacing it, even with an identical copy), drop, sell (sellItem), or the item destroyed by any path (e.g. the RULES-09 Pilfer fumble). Putting the item back on does not bring the effect back."
- "One mechanism: a single engine helper ends the effects linked to a slot, called from every gear-change path" (the load-time reconciliation is 88-02).
- "The use is spent: after an early end the item is ready again exactly when it would have been had the effect run its full length (remaining effect + cooldown)."
- "Narration: one line per ended effect on the Oracle and a rail card, naming the item and what stops, in the house voice."
- "Cloak of Ether inside rock: allowed, and the hero is entombed ... goes through engine/movement.js#resolveEtherEnd ... No refusal and no warning."
- "Flight ending strands nothing."
- "Joiners: covered by design ... The link and its end helper work on any character sheet (hero or Joiner) and are pinned on a Joiner sheet ... No Joiner item-use system is built here."

Claude's discretion used (CONTEXT "Claude's Discretion"):
- Source shape: `src: { slot, n }` on the timer record; `slot` is one of `SOURCE_SLOTS` (jewelry1, jewelry2, cloak, weapon); stamped only when the use came through a source slot and the item is not consumed on use. A slot's current item is read in one place, `sourceSlotItem(sheet, slot)`: `sheet.worn[slot]` for a worn key, `wieldedStaff(sheet)` for weapon.
- Helper: `endSourceEffects(state, sheet, events, opts)` with opts `{ slots, why, rng, now, quiet }`. It ends every live linked effect whose slot is in `slots` (the slots this gear change touched, so an identical-copy swap ends it) OR whose slot no longer holds an item named `src.n` (the sweep, which is what dropItem/sellItem run). One rule, one place.
- The Crystal Staff's spent use: its record has no cooldown (a staff's economy is charges), so an early end removes the record; the charge it cost stays spent and its `charges:` recharge countdown is never touched. That is the staff's form of "never ready sooner".
- Event: `itemEffectEnded { item, kind, slot, why, left, ready, party?, member? }`; `why` is one of "off" (unequipSlot), "swap" (equipItem / wearItem / takeItem / takeLoot), "destroyed" (Pilfer fumble), "gone" (found by the sweep); `party: true` when the item is in PARTY_WIDE_ITEM_EFFECTS, so the line says the whole party is seen again.
- The natural effect-to-cooldown flip in engine/effects.js drops consumer fields (such as `src`), so a cooling record is byte-identical to today's; the link belongs to the effect phase only.

Why drop and sell need no slot of their own: engine/items.js#dropItem and engine/economy.js#sellItem only ever address `c.items[i]` (a bag index; the shell's Drop/Sell rows are bag rows, src/browser/viewModels.js#dropShelfItems "never a worn slot item, never the wielded weapon"). A worn item or the wielded staff reaches the bag only through unequipSlot or an equip swap, which end its effect. Both still call the helper (its sweep), so the "every gear-change path" rule holds by construction, and tests pin use, take off, drop / sell.
