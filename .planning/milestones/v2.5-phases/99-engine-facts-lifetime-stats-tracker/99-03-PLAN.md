<adapter_spec>
The hooks (CONTEXT D 'Tracker and hooks'; the module-state style copies `bests`, `graveyard` and `runRecordedListener` in engineAdapter.js).
- Imports: `ACHIEVEMENTS_KEY`, `parseRecord`, `serializeRecord` from `./achievementRecord.js`; `beginRun`, `foldAction` from `./achievementTracker.js`.
- Module state, never serialized into GameState: `achievementRecord` (null until the first load), `achievementListener` (null), `achievementQueue` (ops waiting for a load), `achievementLoad` (the in-flight load promise, or null).
- `loadAchievements()`: when a load is in flight, return it; otherwise start one that reads `ACHIEVEMENTS_KEY` with `storage.getItem` (a throw reads as null), sets `achievementRecord = parseRecord(raw)`, then drains `achievementQueue` in order through the apply step, clears the in-flight marker and resolves to the record. Never rejects. Each call re-reads storage; reads are not queued behind writes (storage.js contract), so a caller re-reading in the same session flushes first.
- `getAchievementRecord()`: the current record (deep-frozen by plan 99-02), or null before the first load.
- `setAchievementListener(fn)`: a function registers it (replacing any earlier one); anything else unregisters.
- Apply step for one op, all inside its own try/catch that swallows everything: call `beginRun(record, op.state, { now: op.now })` or `foldAction(record, op.events, op.before, op.after, { now: op.now })`; when `changed`, replace `achievementRecord` and call `storage.setItem(ACHIEVEMENTS_KEY, serializeRecord(achievementRecord))` (one write per changed action, enqueued synchronously so storage.flush() sees it); then notify.
- Queue step: when the record is loaded and the queue is empty, apply at once (synchronously); otherwise push the op and, when no load is in flight, start `track(loadAchievements())` so `waitForPending()` and the background flush cover it.
- Notify: when a listener is set and any of `unlocks`, `reveals`, `progress` is non-empty, call it once with `Object.freeze({ unlocks, reveals, progress })` (the tracker's arrays are already frozen); a sync throw or an async rejection is swallowed, exactly like `notifyRunRecorded`.
- `dispatch()`: inside the existing try, right after the existing `died` / dev block and before `decorateMisses`, when neither `before.dev` nor `currentState.dev` is true, queue `{ kind: "fold", events, before, after: currentState, now: Date.now() }` with the raw engine `events` (not the decorated copy).
- `startNewRun()`: after `initRun(...)` and `persist()`, when `state.dev` is not true, queue `{ kind: "begin", state, now: Date.now() }`. This is Tourist's one hook: startNewRun is the seam every player-started delve passes through (the roller and the dev row). `initRun()` itself is not hooked, because its other callers are boot()'s never-persisted pre-title fallback run and dispatch()'s fail-closed recovery run, neither a delve the player started.
- `boot()`: `await loadAchievements()` right after `await loadRunHistory()`.
</adapter_spec>
