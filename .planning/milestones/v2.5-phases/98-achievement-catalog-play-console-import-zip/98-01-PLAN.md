<catalog_spec>
This block is the exact data every entry carries (CONTEXT 'Points', 'Types', 'Hidden achievements and who reveals them', 'List order', 'What counts'). Copy it; do not reinterpret it.

Field order inside every entry literal (plan 98-02 anchors on it, so keep it): id, name, description, line, trigger, threshold, tier, points, initialState, type, steps, reveals, listOrder, icon.
- name, description, line: empty strings in this plan.
- tier: 1 to 4 on a tiered entry, null otherwise.
- steps: equals threshold on an incremental entry, null on a standard one.
- reveals: an array of ids, empty when the entry reveals nothing.
- listOrder: 10 x the 1-based position in the sequence below.
- icon: `{ play: "play/ach_<id>.png", ingame: "ingame/ach_<id>.png" }` (the same relative paths the manifest holds in file_play and file_ingame).
- threshold semantics: the achievement is met when the measured value is at least the threshold. A null threshold means the trigger has no number.

Trigger shapes (every key of the kind is present on every trigger of that kind, null when unused):
- lifetimeCounter: `{ kind, counter, group }`. group is a BESTIARY key for the kills counter and null for every other counter.
- singleRunBest: `{ kind, metric, race, parentClass }`. race and parentClass are null or a RACES / CLASSES key that filters which runs count.
- singleRunFlag: `{ kind, flag }`. When the entry's threshold is a number it is the floor on which the flag is judged (the flag must still hold on reaching that floor); null threshold means the moment the flag holds.
- deathCause: `{ kind, causes, floor }`. causes is an array of CAUSE_TEXT keys, or null for any real death (every cause except abandon). floor is null or a floor number the death must happen on.
- lifetimeFlagPair: `{ kind, flags }`. flags is an array of two lifetime flag ids; the achievement is met when both are set.
- distinctSetCount: `{ kind, set }`.

TRIGGER_VOCABULARY (export, frozen, all strings identifier-like so the voice audit never reads them as copy):
- kinds: lifetimeCounter, singleRunBest, singleRunFlag, deathCause, lifetimeFlagPair, distinctSetCount
- counters: deaths, kills, joinersAccepted, joinersFallen, parleysWon, trapsSurvived
- metrics: depth, days, wilmstHeld, fleesWon
- runFlags: fullyDressed, nakedAtFirstStep, noHealingPotion
- lifetimeFlags: diseaseLeftOnOneHp, poisonLeftOnOneHp
- sets: subClassesDelved

What each vocabulary word measures (document in the module header; Phase 99 implements it): deaths is real deaths with abandons excluded; kills is every foe that dies in the hero's fights whoever struck it (hero, Joiner or summon) plus Walking Dead destroyed by Turn Undead; joinersAccepted is joinerJoined events; joinersFallen is memberDowned plus joinerMurdered events; parleysWon is parleyWon events; trapsSurvived is each trapSprung that does not end in a trap death. depth is the best floor reached in a run (state.floor.depth); days is state.day; wilmstHeld is the most wilmst held at once in a run (spending never counts against it); fleesWon is fled events with reason escaped in one run (door, cloaker, tracked and smoke escapes do not count). fullyDressed is all five equipment slots (weapon not Fists, armour not Nothing, jewelry1, jewelry2, cloak) filled at the same moment; nakedAtFirstStep is all five slots empty at the hero's first step and none filled again before the judged floor (bag items and the torch do not count); noHealingPotion is no potionDrunk of a healing potion by the hero in the run (a Joiner's potion and the magic potions do not break it). diseaseLeftOnOneHp and poisonLeftOnOneHp are lifetime flags set when that affliction has once left the hero on exactly 1 HP. subClassesDelved is the distinct sub-classes a delve was started with (an abandoned delve still counts as started).
