Relevant research sections (83-RESEARCH.md): "### Pattern 1", "### Pattern 2", "### Pitfall 1" through "### Pitfall 5", "### Idempotent create with a true server timestamp", "### Composite index declaration", "## Open Questions" item 3.

Sizing and design decisions made here (CONTEXT "Claude's Discretion"):
- Day bound: day x 100 <= steps + 30,000 (a 300-day camp allowance). The committed 1,000-run DAYS-farming measurement (docs/days-farming/days-farm.json) peaks at day 214, so every measured run passes even with zero squares; beyond 300 days each extra day needs 100 more squares, the engine's newDay cadence. Multiplication only, so no rules integer-division question.
- steps is bounded to 999,999, so deepKey needs no min() (rules have no math.min); daysKey's min is a ternary.
- kills <= steps applies exactly as CONTEXT lists it (a hero who kills more foes than squares walked is refused; the runbook records this).
- Other bounds: level 1..THRESHOLDS.length (5), gold 0..10,000,000, sp and acts 0..1,000,000,000, seed 0..9,007,199,254,740,991 (the shell seeds with Date.now()), name 1..40 chars, epitaph 0..400, version 1..64, uid 1..128.
- The run create is one Write with update + updateTransforms + currentDocument.exists=false (Firestore v1 Write.updateTransforms), the atomic equivalent of RESEARCH's two-Write form; 83-08 falls back to two Writes only if the live project refuses it.
- rankOf's count query carries orderBy rankKey DESCENDING so it reuses topTen's DESC index; 83-08 proves every shape live.
- Report limit day bucketing: `day` stores the UTC midnight of the day's first report, as a Firestore timestamp; the rules compare it with request.time.date() (a timestamp holding only year, month and day). The client computes the midnight from its own clock, so a device clock wrong across UTC midnight can be refused for that one send; the sheet then shows the rate-limited message (documented by 83-10).
- A reportLimits write on its own (no report in the commit) passes the reportLimits rule when it is a valid step; that only spends the writer's own allowance, so it is harmless and documented. The report side is what requires the limit step (getAfter).
- Report doc ids are client-generated 20-character [A-Za-z0-9] ids (Firestore's auto-id alphabet), because a :commit write needs a full document name.
- Cleanup timestamps: 79.3 already stores filedAt as an ISO-8601 UTC string; 83-10 keeps that type and stores failedAt the same way (ISO strings sort chronologically, so range filters work, and one type avoids splitting old and new docs across a single range filter). reportLimits.last is a real timestamp (REQUEST_TIME) and needs only the automatic single-field index.
