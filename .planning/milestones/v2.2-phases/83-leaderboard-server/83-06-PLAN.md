<objective>
Build the submission side of the board: a write client (submit a run idempotently, rewrite the handle on every run, erase every run), the durable submission queue `ddr.runQueue.v1`, and the once-only backfill of locally recorded season runs.

Purpose: SRV-06 (a durable queue holds every non-dev Compete-ON death until acknowledged, survives relaunch and offline play, backs off, never double-submits, is discarded when Compete turns OFF) and SRV-01's client half (each run stored once; resubmitting never duplicates). Implements CONTEXT "Queue, backfill & live setup" (queue semantics: enqueue on death (non-dev, Compete ON); flush on enqueue, resume and online; exponential backoff; a rules rejection drops the entry with a log line; already-exists is acknowledged; 15 s timeouts; never double-submits; purge() for Compete OFF; the backfill module and its backfillDone flag, with the shell call site in Phase 85), CONTEXT "Identity & the @handle" (a re-roll rewrites handle on all the player's runs; erase = owner deletes all runs, then ddr.identity.v1 is dropped) and CONTEXT "The run document" (dev runs are never submitted). RESEARCH Pitfall 1 / Assumption A3 is closed by design: every ambiguous 400/403/409 on create is settled by a public GET of the doc id.

Output: `src/browser/boardWrites.js`, `src/browser/runQueue.js`, `src/browser/runBackfill.js` and their tests.
</objective>

Decisions made here (CONTEXT "Claude's Discretion"):
- Backoff is record-level: failures counts consecutive transient flush failures; retryAt = now + min(30,000 x 2^(failures - 1), 1,800,000) ms; flush({force: true}) ignores retryAt (the shell passes force on the online event in Phase 85); a success resets both.
- The record keeps a settled list (acknowledged or dropped hashes, capped at 500) so a run can never be queued twice.
- Backfilled runs carry version "backfill" because they were played on earlier builds; stamping the current build on them would corrupt per-build balance data (CONTEXT balance tracking).
- boardWrites.eraseMyRuns deletes the anonymous account best-effort before dropping ddr.identity.v1 so no orphaned anonymous account remains; purging the queue on erase is the Phase 85 caller's step.
