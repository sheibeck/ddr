Cleanup query shapes (admin, the Action's service account; every query has a limit equal to the remaining delete budget and orders oldest first):
- Q1 filed-full leftovers: bugReports where status == "filed" AND oracleTrimmed == false, orderBy filedAt ASC (index status + oracleTrimmed + filedAt).
- Q2 filed-expired: bugReports where status == "filed" AND filedAt < (now - 30 days as an ISO string), orderBy filedAt ASC (index status + filedAt). Pre-Phase-83 filed docs have no oracleTrimmed field; this query still retires them 30 days after filing, which is the conservative reading.
- Q3 failed-expired: bugReports where status == "failed" AND failedAt < (now - 30 days as an ISO string), orderBy failedAt ASC (index status + failedAt).
- Q4 limit-expired: reportLimits where last < (now - 2 days as a timestampValue), orderBy last ASC (automatic single-field index).
filedAt stays the ISO-8601 UTC string 79.3 already writes, and failedAt uses the same format: toISOString() strings sort chronologically, so a string range filter is a timestamp filter, and one type avoids splitting old and new documents across a single range filter.
</context>
