## Orchestrator amendment (2026-09-29, overrides any conflicting line below)

**The backfill is decided at the FIRST 2.2 launch, not the first Compete-ON launch.** User rule: runs played with Compete OFF are never uploaded when Compete is later turned on. 2.1.0 runs carry no per-run Compete state, so the Compete setting at the first 2.2 launch stands in for it:
- First 2.2 launch with Compete ON → run the backfill once (bounded to the history's pre-2.2 imports via allowHashes), mark done.
- First 2.2 launch with Compete OFF → make ZERO network calls, mark the backfill done as skipped (e.g. `{v:1, done:true, count:0, skipped:"off"}`), and never upload those runs, even if Compete is turned on later.
- Replace the must_have "it runs once, at the first launch with Compete ON" and the test "A device whose first 2.2 launches ran with Compete OFF and that later launches with Compete ON uploads only the allowHashes runs" with: "a device whose first 2.2 launch has Compete OFF never uploads its 2.1.0-era runs; a later Compete-ON launch enqueues nothing from the backfill". Writing the skipped marker is a local storage write (allowed with Compete OFF; zero network calls).
