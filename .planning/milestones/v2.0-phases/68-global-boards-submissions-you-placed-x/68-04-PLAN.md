<objective>
Build the durable submission queue and the death hook that feeds it. Implements D-01 (every non-dev Compete-ON death submits one score to each of the five current-season boards, with the tag), D-02 (ddr.pgsqueue.v1 through the injected storage; enqueue first, then flush; flush again after sign-in; dedupe and acknowledgement per run hash and board; queue data is shell-owned, never GameState), D-03 (an entry from a season that is no longer current is dropped, not submitted, and reported once for the Oracle), D-04 (Compete OFF: never queued, and purge() empties the queue; signed out with Compete ON: queued until sign-in), D-14 (a placeholder or missing ID skips that board silently without dequeueing the others) and D-10 (the DEEPEST standing requested once after a flush, for the rank line and card). The flush scheduling (one flush in flight, backoff between attempts, forced triggers) is Claude's discretion per 68-CONTEXT and is specified here.

Purpose: no death's score is lost to a dead connection or a missing sign-in, and none is ever submitted twice.
Output: the adapter's run-recorded hook, src/browser/pgsQueue.js, and tests.
</objective>

## Flagged assumptions (unresolved edge rows)

- "Never submitted twice" holds for every path except a process kill in the instant between Play Games confirming a submission and the ack write landing; that run's board would be resubmitted once on the next flush. Play Games keeps only a player's best score, so the repeat changes nothing server-side. The ack is written before the next submission to keep that window to one board.
- Entries whose boards all have placeholder IDs stay queued (up to the 50-entry cap) until a build with real IDs ships, then submit if their season is still current. This is intended: season-1 deaths before the console setup still count.
- A flush whose standing request fails still clears the submitted entries; their placement is not reported later (D-11: nothing on failure).
