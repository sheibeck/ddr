<decisions>
## Implementation Decisions

### Claude's Discretion
All implementation choices are at Claude's discretion — pure infrastructure phase. Constraints that are NOT discretionary (from PROJECT.md / STATE.md engine gate and research):
- Engine stays pure/deterministic; the parity suite must remain byte-identical for solo/empty-party play; `test/parity/prototype-master.js.txt` is never edited.
- The refactor is behavior-preserving: same RNG draw order and count, same events, same state. Prove it with the existing parity suite (683 tests green) plus new behavior-preserving unit tests.
- `pickFoeTarget` must encapsulate the existing PARTY-04 gate (`rng.d(pool)` drawn ONLY when at least one live party member exists) — `engine/combat.js:857-866`.
- `applyFoeDamageToPlayer` must encapsulate the hero-damage pipeline exactly as it is today: Hardiness, `c.halfNext` (Pendant), ward absorb/reflect/shatter, armor soak `rng.d(20)` via `armorSoak(c)`, `struckByFoe` event, `die()` on 0 WP — `engine/combat.js:888-975`. The simplified member branch (no ward/armor) stays distinct but may share the same helper with a mode flag if that keeps draw order identical.
- The fixture inventory is a committed markdown document (suggested: `test/parity/FIXTURE-INVENTORY.md`) enumerating, per fixture file and scenario/seed, the encounter type forced and the creature(s) the prototype's tables roll — generated by actually replaying the fixtures through the sandbox, not by reasoning about seeds. Note explicitly that combat/magic fixtures only force Beasts/Humans (research finding) and which creatures therefore constrain the Phase 18 rebalance.
- The draw-count regression test should count RNG draws (wrap `makeRng` or compare `rngState` cursors) across a full fight for foes with no `abilities` field and pin the count, so Phase 19's ability gate is verifiable as zero-draw.

</decisions>
