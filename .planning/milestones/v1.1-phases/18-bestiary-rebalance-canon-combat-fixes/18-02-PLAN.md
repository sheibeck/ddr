## Assumptions locked by this plan (from 18-RESEARCH.md Assumptions Log / Open Questions, and Claude's Discretion in CONTEXT.md)

- A4 (location): the seam is a NEW top-level file `engine/foeDamage.js` (auto-covered by `formatEventsCoverage`'s top-level `engine/` scan and by `engine-purity`), not a new export inside `combat.js` — keeps the four-modifier surface greppable in isolation and avoids growing the hottest module.
- A2 / A3 (reflect and item damage): treated as PHYSICAL — soakable by `foe.sp.ar`, never multiplied. Rationale: D-06 names spells as the only bypass; a ward bounce and a thrown flask are physical impacts on the foe. `kind: "foe"` (a foe struck by another foe, the `insane` r=2 branch) is likewise physical, unmultiplied.
- `multiplierFor` placement: in `engine/foeDamage.js`, NOT co-located in the content file — `test/determinism/content-is-pure-data.test.js` fails on any function-typed export under `content/` (18-PATTERNS.md's co-location sketch would break it).
- D-07's "critical hit": the seam honors `source.crit` as passed by the caller; 18-03 passes `playerStrike`'s composite `crit` flag (natural 1, plus the engine's skill-granted criticals — Silence/Stealth/backstab/Ninja/Cutthroat — which the engine already treats as the same "critical" concept by doubling damage). One definition of critical, one bypass.
- Multiplier rounding: `Math.round(rawDmg * mult)` — a no-op for today's integer factors, stated so a future fractional row has a defined contract.
- Two-modifier stacking order is multiplier → halfDmg (so a x2 spell on a halfDmg foe returns the raw value: `ceil(round(5*2)/2) = 5`, whereas halve-then-multiply would give 6). No creature today has both; the order is pinned by a synthetic test so a future addition inherits a defined rule.
- Soak event amount: `amount` is the post-multiplier, post-halving damage that would have landed (what the armor actually ate), not the caller's raw roll.
