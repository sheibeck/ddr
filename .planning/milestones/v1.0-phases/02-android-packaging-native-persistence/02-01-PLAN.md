## Phase Goal

**As a** Mazeworld player, **I want to** have my run saved after every move and whenever I leave the app, **so that** I can be interrupted or fully close the game and reopen it exactly where I left off, with my best depth and graveyard intact.

*(Derived from the ROADMAP Phase 2 `**Goal:**` line, which is outcome-shaped. This phase runs under MVP_MODE; the story frames the player-observable capability the four plans deliver together. This plan builds the durable-storage foundation that capability rests on.)*

<objective>
Build the single shared **async Storage abstraction** every later plan writes through, plus its one-time legacy-key migration — the durable-persistence foundation for SAV-01..05. This plan is pure JavaScript: it introduces no Capacitor runtime import that node or the browser dev loop can trip over, and it is verified entirely headlessly with `node --test`.

Purpose: Give the app ONE durable, versioned, integrity-checked save surface (Capacitor Preferences on native, localStorage in the dev loop) so run state, best depth, and the graveyard all survive an app restart — and so the classic script and engine adapter can later converge on it (02-03), closing the dual-write hazard.

Output / artifacts this plan produces:
- `src/browser/storage.js` — the async `getItem`/`setItem`/`removeItem`/`flush`/`migrateLegacyKeys` module, exposed as `window.mzStorage`.
- `test/persistence/harness/fakePreferences.js` — reusable async fake-Preferences mock (used by this plan and 02-03).
- `test/persistence/storage.test.js`, `test/persistence/storage-migration.test.js` — the Wave-0 unit coverage.

Artifacts the FULL phase produces (for downstream reference): this Storage module + migration; the Capacitor project (`capacitor.config.json`, `www/`, `android/`); `tools/build-www.mjs`; `android/gradle.properties` JDK pin; self-hosted fonts; native chrome resources.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| stored bytes → app on load | Preferences/localStorage contents are untrusted input on read (a rooted device, file manager, or a torn write can produce malformed/tampered data) |
| legacy localStorage → Preferences (migration) | migrated data crosses into the durable store; must be validated, not blindly trusted |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-02-01 | Tampering | storage.getItem feeding a run save into the app | medium | mitigate | getItem returns a raw string that engine/saveState.js validateSave() checks fail-closed (malformed/shape/newer-version rejected to a fresh run); migrateLegacyKeys validates the run save via validateSave before copying — corrupt/tampered legacy data is not migrated |
| T-02-02 | Denial of Service (self-inflicted) | a rejected native Preferences read / corrupt value on boot | medium | mitigate | every read is wrapped to resolve null on throw/reject (never an unhandled rejection that could crash the WebView JS context); the caller falls open to a fresh run — preserves engineAdapter's existing fail-open contract |
| T-02-03 | Tampering | rooted-device edit of SharedPreferences to alter best-depth/graveyard | low | accept | single-player, no leaderboard — a self-tampered personal value is accepted as low-severity (per engineAdapter.js doc comment and PITFALLS Pitfall 12); validateSave still guards the run save against structural corruption |
</threat_model>
