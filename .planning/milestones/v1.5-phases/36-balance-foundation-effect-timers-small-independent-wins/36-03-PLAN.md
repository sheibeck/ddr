<objective>
A dead foe can never be the target (TGT-01) and tapping a dead card does nothing while the auto-switch can never race a guarded tap into a mis-target (TGT-02). Per CONTEXT §"Dead-Foe Targeting (TGT-01/02)": export a pure `normalizeTarget(combat)` from `engine/combat.js` implementing the EXACT lazy rule strike (`combat.js:461-462`) and cast (`magic.js:97`) already apply, refactor those two call sites onto it (behaviour-identical), and have the shell call `normalizeTarget(S.combat)` after every combat dispatch, before `renderEncounter()` — so `combat.target` stays byte-identical in every parity fixture (it IS part of the combat comparable) and the Phase 34 ruling "targeting stays the guarded shell mutation, no engine retarget action" holds. Any kill source is covered by that one seam (hero's blow, Joiner's blow, Freeze, foe-on-foe, DOT): the normalize runs on every dispatch, not per source. Dead cards: keep the existing `if (c.alive)` guardTap wiring, add `aria-disabled="true"` on dead cards, pin with a shell test. Race protection: the normalize runs before the re-render, so `ARM_DELAY_MS` (250 ms) stamps on the settled roster; test that a tap inside the arm window after a kill is refused and a tap on a live card after the window targets the tapped index.

Discretion resolved (CONTEXT "Whether normalizeTarget also guards foes being empty"): when NO foe is alive the helper assigns `-1` — that is exactly today's `findIndex` result at both engine call sites and must stay so for byte-identity; the shell never reaches that case (combat is null once the room clears). Null/undefined `combat` or a non-array `foes` returns without touching anything.

Research note: `.planning/research/ARCHITECTURE.md` §5 suggested calling the helper from `killFoe`; CONTEXT locks the shell-side post-dispatch call instead (keeps `combat.target` byte-identical in fixtures) — honour CONTEXT.
