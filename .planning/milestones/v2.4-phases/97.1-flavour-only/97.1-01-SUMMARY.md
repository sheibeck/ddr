# Phase 97.1 Plan 01: Module surfaces draw flavour only Summary

The six src/browser modules (roller, heroTab, gearTab, gearSheet, storeScreen, finalSheet) no longer create any RULES control or rules body; every flavoured row shows its flavour line alone, an unflavoured row keeps today's text, and the exact rules text is asserted on the view models instead of the DOM.

## What was built

- **Task 1 (4d017529):** roller.js (three imports again; a reveal group is name plus flavour line, footer lines only for an identity with no flavour), heroTab.js (ability rows, Grimoire, trait line, special skills, dossier). roller.test.js and heroTab.test.js re-pinned; the two retired-control roller tests (RULES tap, Always show) deleted.
- **Task 2 (74f2688f):** gearTab.js (carried list, WORN, BAG, CONSUMABLES), gearSheet.js (one render path; flavoured item drops the effect row via `statKeys`, keeps AR/hp/dice/bulk rows as plain `p.mw-gsheet-note.mw-gsheet-stat`, container hidden only when none remain), storeScreen.js (bare shelf rows), finalSheet.js (tricks, worn, bag). Six module tests re-pinned; three new gear-sheet-dom cases (flavoured jewel hidden and empty, flavoured armour rows, unflavoured jewel still draws its effect row) and one gear-sheet-model test for `statKeys`.
- **Task 3 (9f1be38b):** nine shell-snapshot fixtures regenerated and declared in the shell-tab-snapshots and shell-ability-states headers: thief.hero, mu.hero, thief.gear, mu.gear, thief.gear-sheet-bag, thief.gear-sheet-worn, thief-store.store, mu-store.store, fighter.hero-in-combat.
