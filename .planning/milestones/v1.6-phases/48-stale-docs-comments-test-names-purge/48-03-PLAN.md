<phase_ground_rules>
These rules apply to every task in every Phase 48 plan; they are restated verbatim in each plan.

- **Engine-gate fence (every commit):** `engine/`, `content/` and `test/parity/fixtures/` change on COMMENT LINES ONLY, proven by a comment-stripped diff (`node tools/comment-only-diff.mjs 649de2b engine content test/parity/fixtures` — every changed file reports `comment-only:`; fixtures are JSON and must not appear at all). `test/parity/prototype-master.js.txt` is never edited (hash `a1f4d0dc29782218d8e5aab65bc5989c33f917f0`).
- **Test invariant:** `npm test` pass count stays exactly **3,288** / fail 0 at every commit of Plans 01-04 (renames only; no test added or deleted — a test that must go needs its reason in the SUMMARY). Plan 05 adds the tripwire's own tests and records the new count as "3,288 + N".
- **Phase 47 DOM-snapshot smoke:** `node --test test/unit/shell-tab-snapshots.test.js` stays 10/10 with `git diff --stat -- test/unit/fixtures/` empty — a comment edit cannot move it, so a fixture diff means a code line was touched.
- **Never `git add -A`.** Stage by path. Never touch `icons/` or `sfx/`. `.planning/` is history — out of scope for the sweep (SUMMARY/STATE/REQUIREMENTS updates at plan close are the normal exceptions).
- **No wholesale comment-volume purge** — Phase 47's line-budget ruling closed that. This phase removes stale *meaning*, not comment volume. A comment that explains a retirement by name ("was a toast; the rail owns feedback since Phase 35") stays when it still helps a reader — it must not describe the retired thing as live.
- **Judgment call 1 (CONTEXT, user-reversible):** `classic script` is a LIVE term — it names `mazeworld.html`'s non-module `<script>` block. It stays; the tool reports it as an informational row. A comment that says the classic script *is an engine*, *mirrors the engine*, or names a specific classic `X()` duplicate as if it still existed IS stale and goes.
- **Judgment call 2 (CONTEXT, user-reversible):** allowed survivors are (A) tests/lines that ASSERT a retirement (the Phase 35 invariant suite, `assert.equal(... , 0)`-style pins and their titles), (B) prose retirement statements that still help a reader, (C) tolerant-load legacy-key reads and their pins (`engine/saveState.js#foldLegacyCounters`, the parity comparables' prototype-side strips, `test/unit/item-activation.test.js`'s fold pins, `save-validation.test.js`'s OLD-SAVE inputs), (D) inert legacy keys inside hand-built test-state literals (`flightLeft: 0, flightCooldown: 0` / `won: false` in `fixedState()`-style objects) — Plan 04's last task removes these in one revertable commit; until then they are counted, listed, and not edited. Every survivor is an `ALLOWED` entry in `tools/stale-terms.mjs` with file + match + reason — nothing else survives.
- **Windows executor environment:** Git Bash, no `jq`; heredocs and `node -e` one-liners mangle backslashes — write any regex-heavy script to a file with the Write tool, never a heredoc. Rename files with `git mv`, never delete + create.
- **Line numbers drift:** anchor by the quoted text; numbers below were measured at HEAD `649de2b`.
- **Verification agents are off:** the acceptance criteria ARE the verification — every `<verify>` command is literal, with its expected output.
- **Test bodies: the bounded rule.** The CONTEXT says "test bodies and assertions are not touched (a body that needs changing is a behaviour question — flag it, don't fix it here)". This phase reads that as: no expected value, condition, fixture literal, event type or field name changes. Two edits are NOT behaviour questions and ARE in scope: (i) renaming a local identifier whose name contains `toast`/`Toast`/`TOAST` to its `line`/`Line`/`LINE` equivalent, consistently within its scope (`const toast = LINE_FOR.x(e)` → `const line = …`; `TOAST_CASES` → `LINE_CASES`; `backstabToast` → `backstabLine`; `toasts = linesForAction(…)` → `lines = …`); (ii) rewording an assertion MESSAGE string (the trailing message argument of an `assert.*` call) — "should yield exactly one toast" → "… one line". A test TITLE is not a body: rename it. A comment inside a body is a comment: rewrite it. If a rename trips another test that pins the old text: reword so the pinned substring survives when it is not itself stale; if it IS the stale text, revert and list the line as a survivor with the pinning test's name — never edit an expected value.
</phase_ground_rules>
