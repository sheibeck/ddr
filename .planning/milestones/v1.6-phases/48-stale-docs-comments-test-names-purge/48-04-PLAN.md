- **No wholesale comment-volume purge** — Phase 47's line-budget ruling closed that. This phase removes stale *meaning*, not comment volume. A comment that explains a retirement by name ("was a toast; the rail owns feedback since Phase 35") stays when it still helps a reader — it must not describe the retired thing as live.

A comment that says the classic script *is an engine*, *mirrors the engine*, or names a specific classic `X()` duplicate as if it still existed IS stale and goes.
- **Judgment call 2 (CONTEXT, user-reversible):** allowed survivors are (A) tests/lines that ASSERT a retirement (the Phase 35 invariant suite, `assert.equal(... , 0)`-style pins and their titles), (B) prose retirement statements that still help a reader, (C) tolerant-load legacy-key reads and their pins (`engine/saveState.js#foldLegacyCounters`, the parity comparables' prototype-side strips, `test/unit/item-activation.test.js`'s fold pins, `save-validation.test.js`'s OLD-SAVE inputs), (D) inert legacy keys inside hand-built test-state literals (`flightLeft: 0, flightCooldown: 0` / `won: false` in `fixedState()`-style objects) — Plan 04's last task removes these in one revertable commit (the 46-02 SUMMARY handed the `won: false` list to this phase); until then they are counted, listed, and not edited. - **Verification agents are off:** the acceptance criteria ARE the verification — every `<verify>` command is literal, with its expected output.

This phase reads that as: no expected value, condition, fixture literal, event type or field name changes. Two edits are NOT behaviour questions and ARE in scope (Plans 03-04): (i) renaming a local identifier whose name contains `toast`/`Toast`/`TOAST` to its `line`/`Line`/`LINE` equivalent, consistently within its scope; (ii) rewording an assertion MESSAGE string. A test TITLE is not a body: rename it. A comment inside a body is a comment: rewrite it. If a rename or comment rewrite trips another test that pins the old text: reword so the pinned substring survives when it is not itself stale; if it IS the stale text, revert and list the line as a survivor with the pinning test's name — never edit an expected value. Task 3's inert-key removal is the one further body edit this phase makes, in its own commit, with a revert-not-fix rule.
