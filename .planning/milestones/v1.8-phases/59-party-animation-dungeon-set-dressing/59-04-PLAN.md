**Why `from` is captured before the dispatch.** `paint()` runs inside `stepWith` after the engine has moved the party, and draw() → positionCanvas() → positionPartySprite places the marker on the NEW cell (no glide is active yet). The glide must start from where the marker was drawn BEFORE the step: the old cell, or the in-flight point when a previous glide is still running. That value exists only before the dispatch. The controller then renders `from` synchronously, in the same task as `paint()`, so the browser never presents the intermediate new-cell placement.

**Why the trigger sits after the camera lines.** Keeping the two pinned lines byte-identical preserves shell-map-viewport (m). Starting the camera nudge first and the marker glide second, back to back, gives both the same start instant and the same `PAN_MS` ease-out curve, which is D-03's "marker and map move together".
