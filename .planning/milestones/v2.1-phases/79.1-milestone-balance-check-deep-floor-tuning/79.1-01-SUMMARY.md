# Phase 79.1 Plan 01: The v2.0 Pre-Milestone Baseline Summary

The milestone's balance baseline is on file at the v2.0 tag. The 200-seed natural run is reused from the committed Phase 72 BEFORE readout, whose engine, content and tools match v2.0 byte for byte. Three readouts were taken once each at v2.0 in a detached scratch worktree: the tail row (every deep, Sorcerer and Troll slice), the 143-cell class and race matrix, and the 1,000-seed natural run. ## Read this first: v2.0 is not the same ruleset as FINAL

**The v2.0 baseline HAD the per-floor descent heal (`HERO_REGEN_PER_FLOOR` = 0.25 × max hp on every arrival) and did NOT have 79-02b's Joiner-defences rule** (a Joiner borrowing the hero's defences). Both changed after v2.0:

- 79-02c removed the descent heal (user ruling 2026-09-27).
- 79-02b made a Joiner use only its own defences.

Both changes make the game harder. Part of any v2.0-vs-FINAL gap comes from these two rulings, not from dial tuning. Every later comparison against this table must carry this caveat.

## Deviations from Plan

**1. [Tooling] Waited with a polling loop, not a Monitor tool**
- **Found during:** Task 2
- **Issue:** The plan asks for a Monitor watching each background run. This agent has no Monitor tool.
- **Fix:** Each run went through `run_in_background`. A foreground Bash loop (at most 600,000 ms per call) then polled every 10 s for the run's `exit=` line. The same completion condition was checked and the runs stayed strictly one at a time. Each background task also sent its completion notification. No process was left running.
- **Files modified:** none

Otherwise the plan ran as written. There was no fallback, the fresh gate did not open (so there is no overlap to accept), no engine, content or test file changed, and prototype-master.js.txt was not touched.
