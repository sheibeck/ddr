## Flagged assumptions (surfaced, not silently decided)

- **Everything moves, at every depth.** 79.1-03 could rely on "only floors 13+ move". This lock can't: the searched dials are global.
  - FOE_HIT_SCALE, FOE_HP_SCALE and HAZARD_SCALE act as base + perDepth x d from floor 1.
  - ENCOUNTER_DOTS sets the floor-1 feature count.
  - HERO_HP_SCALE scales chargen HP and the Table 4 HP dots.
  - HERO_SP_SCALE scales every SP grant.

  So FITTED_CURVE_PINS moves at depths 2-50, not only past 12, and the bot state pins move from their first dial-reading step. That is expected, and each one is still traced.
- **FOE_LEVEL leaves floor 1 alone.** At every in-bounds value (base <= 1.0, perDepth <= 0.3), round(base + perDepth) = 1, so floor 1's foe level can't move. If the orchestrator widened those bounds in 79.2-02 so that base + perDepth >= 1.5, floor 1 foes change tier. The lock still proceeds (it is the confirmed row), but the SUMMARY flags it for 79.2-04's parity predictor.
- **A lock equal to START changes no value.** If 79.2-02 recorded "PASS at START", early-lock.json equals start.json. Then the lock is only the traced test and the overlay layer, nothing is re-pinned, and the SUMMARY records "measured zero".
- **Worktree CRLF noise.** STATE records 7 CRLF doc-ledger failures that appear only in worktrees. The plan-base `npm test` run captures the failing set, and "no new failure" is measured against it.
