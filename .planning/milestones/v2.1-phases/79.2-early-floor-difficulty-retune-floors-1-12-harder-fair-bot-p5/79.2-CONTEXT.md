## Implementation Decisions (user rulings, 2026-09-27)

- **The complaint:** "we need to bring the difficulty back up on floors 1 - 12. Just too easy." The user played the Pixel 7 debug build from a5af69ee, which already had no per-floor heal (79-02c) and Joiner-only defences (79-02b).
- **Timing:** "I want early floor difficulty change now. Before we do a new push to the closed test." This lands in THIS milestone, before the release build and the closed-test push.
- **Yardstick, the user's choice "Lower the bot target":** the fair bot plays much worse than a human. Retune floors 1–12 so a typical FAIR-BOT run dies around floor **3–4** (fresh p50 death depth 3–4 at 1,000 seeds). That should put skilled human runs near the standing 5–7 human average (memory: depth-20 target, updated 2026-09-27). This supersedes the fair-bot p50 5–7 band from Phase 54 (USER RULING D) for floors 1–12.
- **Band shape stays:**
  - Floors 1–4 are the Filter: high variance, where bad drops and early mistakes kill, not a flat wall.
  - Floors 5–8 are the Wall.
  - The survival-curve targets for floors 1–12 (the Phase 54 band fit in tools/lib/fit-score.mjs and band-readout.mjs) are re-derived so their p50 lands at 3–4. The planner proposes the new per-floor survival targets. They are a ruled-value change the user has already authorised through the p50 3–4 ruling.
- **Tail unchanged:** the 79.1 ruled tail targets (fresh reach-20 ≤ 1%, reach-21 < 0.5%, deep-slice targets, the rotation constraints) must still PASS. 79.1-02 found four at their limit and fresh reach-20 at 0/1,000; a harder early game makes the tail harder still. Report any tail change with evidence; don't compensate silently.
- **Classes:** the existing class constraint holds (|class p50 − pooled| ≤ 2 floors).
- **Order:** measure AFTER the 2026-09-27 rule changes merge: quick 260927-rsx (every foe-targeted spell resistible on a half-intel scale; a resisted spell has no effect) and 260927-opf (one-shot strikes once per fight). Both make the game harder. Take a fresh START measurement on that code before sweeping.
- **Protocol:** the checkpointed fit protocol (memory: checkpointed-fit-protocol). Blocks of 10; a failure pattern (ruling F) goes back to the orchestrator; the orchestrator adjusts search parameters; engine-shape changes go to the user; run out the budget only while converging. Every block passes `--transcript` (80-06). `--search` needs a coordinate-covering `--start` (a `{}` start crashes fit-score's applyStep). HERO_REGEN_PER_FLOOR no longer exists (79-02c): SEARCH_PLAN has 9 coordinates, and an unknown dial throws.
- **Lock and gate:** as 79.1-03: lock the best dial set into engine/difficulty.js with a traced test, re-pin only what moves (traced), declare the fixture moves in FIXTURE-INVENTORY, and get a green `npm test`, parity and boot:check. Record the before/after in docs/DIFFICULTY-RETUNE.md.
- **After this phase:** 79.1-04 (final readouts and verdicts, trimmed per the "measure, then ship" ruling) runs on the locked code, then the Phase 80 release build, then (ask first) the closed-test push.
