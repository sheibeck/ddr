## Decisions Made
- Held's foe-card description stays ONE generic sentence across every kind (never per-kind text) — reusing the PERMANENT "Frozen"/"Stupefied" entries' own DESC text for a temporary hold would be factually misleading ("fairly final" is not true of a 3-round hold), and the plan's own `<behavior>` block never pins Held's desc content the way it pins Unmoved's ("whose desc names sleep") — a deliberate simplification, documented rather than silently chosen.
- The Unmoved chip's desc is built by `descFor` interpolating a `%s` placeholder stored in `FOE_CONDITION_DESC.unmoved` with a small local effect-word map, avoiding 7 new COPY/DESC key pairs (one per resistible effect) while still satisfying "whose desc names the effect" — mirrors the `dot` entry's own poison/ice indirection precedent already established in this table.
- Joiner Weaken's resist marks every LIVE foe `resisted: "weaken"` (not just the aimed-at target), per 75.3-CONTEXT's own flagged assumption that Weaken is "one roll for the room" — narrated once (the aimed-at foe's own `controlResisted` event), with every other foe's chip-only mark silent (avoids N duplicate Oracle lines for one cast).
- `controlResistFacesFor`'s 19-face ceiling is hardcoded (never a dial), structurally guaranteeing RULES-18's own prohibition ("MUST NOT make control impossible at any depth") — a released `resistCap` above 19 can still never zero out the controller's own top face.
- `test/unit/control-at-depth.test.js`'s determinism idiom (`forceControlResist`, searching `state.acts` 0..5000 against the REAL `controlResistCheck`) required care around each test's `rng.getState()` stub: most tests use a fixed-cursor `fakeRng` (cursor 0, matching the SAME stub the real call sees), while the one draw-parity test uses a `trackingRng` whose `getState()` reflects the real running draw count, since that specific claim ("the main cursor advances identically regardless of outcome") is meaningless under a fixed-cursor stub.
