<objective>
Build the server half of bug reporting. A scheduled GitHub Action in sheibeck/ddr reads new reports from Firestore with a service account and files each one as a public, labelled issue on sheibeck/ddr. The player's text can't ping anyone, and the Oracle sits collapsed and trimmed. Each report is marked filed and is never filed twice.

The runner uses Node 22 built-ins only, with an injected fetch and clock so every path is unit-tested.

Purpose: BUG-04 and D-02, D-05, D-14. It leaves the D-17 hooks: `--dry-run` for the filer and a `dry_run` input for the workflow.

Output:
- tools/bug-reports/issue-format.mjs and tools/bug-reports/file-issues.mjs;
- .github/workflows/bug-reports.yml;
- the .gitignore patterns;
- three test files.
</objective>

## Flagged assumptions

- **Ordering by createTime.** Firestore's REST `runQuery` can't order by the document's server createTime. The runner queries `status == "new"` with limit QUERY_LIMIT (200), then sorts client-side by `createTime` and files the oldest 20. With a backlog over 200, the oldest might not be in the first page; docs/BUG-REPORTS.md (79.3-06) records this edge. A composite index is avoided on purpose, since single-field equality needs none.
- **The reconcile scan.** Stale reports are reconciled against the most recent 100 `player-report` issues (list endpoint, all states, newest first), not the search API. The search index lags, and HTML comments may not be searchable. The marker must be the body's first line, and player text has `<` escaped, so a player can't forge a marker.
- **The retry cap.** A report whose issue creation keeps failing would otherwise retry every 15 minutes forever. `attempts` is incremented on each lock; at MAX_ATTEMPTS a stale report with no marker becomes `status: "failed"` and is logged. That goes beyond D-14's list, but only as a guard, and it never files a report twice.
- **The precondition failure shape.** Firestore reports a lost `currentDocument.updateTime` precondition as a non-2xx with `error.status` FAILED_PRECONDITION (HTTP 400 or 409). The runner treats that status, or any 409/412, as "someone else has it; skip".

<interfaces>
- **The report document** (79.3-01's client, D-11). Fields:
  - `schema` 1 and `status` "new";
  - `text` (1 to 2,000 chars), `oracle` (plain text, oldest line first, `\n`-joined) and `oracleLines`;
  - `version` (e.g. `2.1.0 (11)` or `dev`), `platform` (`android`, `web` or `node`), `device` (the user agent) and `clientTime`;
  - optional `run` = `{ depth, cls, sub, race, level, steps, day, dead }`.

  The Action adds `status` "filing" / "filed" / "failed", `attempts`, `issueNumber`, `issueUrl` and `filedAt`.
- **Firestore REST, authenticated.** Use `Authorization: Bearer <token>` against `https://firestore.googleapis.com/v1`.
  - `POST /projects/{p}/databases/(default)/documents:runQuery`, with body `{ structuredQuery: { from: [{ collectionId: "bugReports" }], where: { fieldFilter: { field: { fieldPath: "status" }, op: "EQUAL", value: { stringValue: "new" } } }, limit: 200 } }`. The response is a JSON array of `{ document?: { name, fields, createTime, updateTime }, readTime }`; entries without `document` are skipped.
  - `PATCH /projects/{p}/databases/(default)/documents/bugReports/{id}?updateMask.fieldPaths=status&updateMask.fieldPaths=attempts&currentDocument.updateTime=<RFC3339, encodeURIComponent>`, with body `{ fields: { status: { stringValue: "filing" }, attempts: { integerValue: "1" } } }`.
- **Google OAuth.**
  - `POST https://oauth2.googleapis.com/token`, `Content-Type: application/x-www-form-urlencoded`, body `grant_type=urn:ietf:params:oauth:grant-type:jwt-bearer&assertion=<jwt>`. The response is `{ access_token, expires_in }`.
  - JWT header: `{ alg: "RS256", typ: "JWT", kid: sa.private_key_id }`.
  - JWT claims: `{ iss: sa.client_email, sub: sa.client_email, aud: "https://oauth2.googleapis.com/token", scope: "https://www.googleapis.com/auth/datastore", iat, exp: iat + 3600 }`.
  - Every part is base64url with no padding. Sign with `crypto.sign("RSA-SHA256", Buffer.from(signingInput), sa.private_key)`.
- **GitHub REST.** Base `https://api.github.com`. Headers: `Authorization: Bearer <GITHUB_TOKEN>`, `Accept: application/vnd.github+json`, `X-GitHub-Api-Version: 2022-11-28`, `User-Agent: ddr-bug-reports`.
  - `POST /repos/{o}/{r}/labels` with `{ name: "player-report", color: "d93f0b", description }`: 201, or 422 when it already exists.
  - `GET /repos/{o}/{r}/issues?labels=player-report&state=all&sort=created&direction=desc&per_page=100`.
  - `POST /repos/{o}/{r}/issues` with `{ title, body, labels: ["player-report"] }`: 201 with `{ number, html_url }`.
