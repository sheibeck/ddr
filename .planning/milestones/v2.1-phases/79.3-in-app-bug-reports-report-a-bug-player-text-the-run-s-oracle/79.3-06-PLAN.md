## Flagged assumptions

- **Diagnostics interplay.** LISTING.md's existing "Open decision for the console step" already considers declaring Diagnostics as not optional, if the Play Games SDK sends anything at launch. Bug reports now declare Diagnostics as optional. Play keeps one entry per data type, so if the PGS capture shows SDK traffic, the combined Diagnostics entry becomes not optional. The paragraph is updated to say so, and the decision stays the user's at console time.
- **"Not shared" for bug reports.**
  - Firestore is Google Cloud, processing on the developer's behalf: the service-provider exemption.
  - Posting the report publicly on GitHub is the player's own disclosure, stated before Send: the user-initiated exemption (answer/10787469).
  This reasoning is recorded for the user, who makes the console call.

5. **The Action.**
   - Schedule, dispatch and the dry run: `gh workflow run bug-reports.yml --repo sheibeck/ddr -f dry_run=true`, then `gh run watch`.
   - Permissions and the concurrency group.
   - At most 20 per run, oldest createTime first. The limitation: runQuery fetches up to 200 `new` documents unordered, so with a larger backlog the oldest may wait an extra run.
   - The lock with its updateTime precondition, and the hidden marker.
   - The 10-minute stale reconcile against the latest 100 `player-report` issues, and the 3-attempt cap leading to `failed`.
   - The label, created if missing (a 422 is ignored).
   - The issue format: title, neutralised @ and #, escaped HTML, the details table, the collapsed Oracle, and the 65,536-character trim.
6. **Operations.**
   - Sending a test report (`node tools/bug-reports/send-test-report.mjs`, and `--dry-run`).
   - **The 60-day rule:** GitHub disables scheduled workflows in a public repo after 60 days with no repo activity. Reports wait safely in Firestore until someone re-enables the workflow in the Actions tab, or with `gh workflow enable bug-reports.yml --repo sheibeck/ddr`.
   - The Spark free quota (tell the reader to check the Firebase console for the current daily write and read allowance).
   - The spam kill switch: deploy a rules file with `allow create: if false` and disable the workflow. App Check is the deferred fix (CONTEXT).
   - Deleting a report on request: delete the Firestore document in the Firebase console, and the issue with `gh issue delete <n> --repo sheibeck/ddr --yes` (admin).
7. **Keys and rotation.**
   - **The API key:** a public identifier restricted to the Cloud Firestore API, living only in `src/browser/bugReportConfig.js`. To rotate: create a new restricted key, ship an update with it, then delete the old key once the update is live. Builds holding the old key then get "refused".
   - **The service-account key:** it lives only in the `FIREBASE_BUG_REPORTS_SA` repo secret, and the Action reads it; it never touches the repo or www. Rotation:
     1. `gcloud iam service-accounts keys create <scratch path>`;
     2. `gh secret set FIREBASE_BUG_REPORTS_SA --repo sheibeck/ddr < <file>`;
     3. delete the local file;
     4. `gcloud iam service-accounts keys delete <old key id>`.
   - The service account is `ddr-bug-reports@delve-die-repeat-6ba5f.iam.gserviceaccount.com` with `roles/datastore.user`.
8. **Troubleshooting**, one line each:

   - a 400 or 401 from the token call (a revoked key, or clock skew);
