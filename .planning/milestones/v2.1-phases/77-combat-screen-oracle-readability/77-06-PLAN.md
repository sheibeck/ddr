## Flagged assumptions (surfaced, not silently decided)

- **The family wording is the bestiary key, plural, upper-cased** ("ZIT · BEASTS"), per CONTEXT's example; the todo's singular idea ("Gremlin · Demon") is not used.
- **"Unidentified SOMETHING" is read as an unknown `type`.** The engine has no separate "unidentified foe" state today; foe details prints FAMILY UNKNOWN exactly when `type` is not an ENC_TYPES key, so the card uses that same predicate. If a future phase adds hidden foes, the predicate is the one place to extend.
- **The most likely CMBUI-12 cause (to be proven or disproven by the reproduction):** the oldest row of a tile-started fight is the encounter-start line, whose own Oracle sentence has no dice (the table dice sit on the ORACLE_ONLY encounterRolled event), so renderFightLog gives it no tap handler at all. A second possible cause is the Android gesture area covering the bottom of the sheet. The plan fixes the first in data and hardens the layout against the second; the executor records what the reproduction actually showed.
- **A row with no dice anywhere stays plain.** The action that raises a fight is logged as ROUND 1 (Phase 35's routing), so a camp ambush or a move with a terrain line can put a dice-less line (rations, rest, wading) at the very bottom. Phase 71's R-23 says such a row gets no handler, and CMBUI-12 is about rows that have a roll. If the user wants every row tappable (for example revealing "no dice for this one"), that is a small follow-up, not decided here.
