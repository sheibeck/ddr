# Parity Fixture Inventory — which bestiary creatures the frozen fixtures roll

This document is generated by REPLAYING every parity fixture through the
parity harness (`node tools/fixture-inventory.mjs`), never by reasoning about
seeds or reading `content/bestiary.js`'s arrays by hand. It exists to answer
one question precisely: **which `content/bestiary.js` creatures does the
frozen parity suite depend on?** Phase 18 (BEST-03 / FID-05) consults this
document before touching any bestiary number — a rebalance of a creature
listed here as fixture-exposed requires a narrow, named `comparables.js`
carve-out; every other creature is free to change.

1. Run `node tools/fixture-inventory.mjs`.

   bracket the table below (`begin`/`end`), replacing the existing table.

If `fixture-inventory.test.js` breaks after an INTENTIONAL fixture/seed/
bestiary change, regenerate this document AND update the test's pinned array
together, in the same commit, with a stated rationale — never just edit the
pinned array in isolation (see `.planning/research/PITFALLS.md` Pitfall 14:
never silently regenerate expected values without a paired, reviewable

## Parity-exposed bestiary surface

The complete parity-exposed bestiary surface is exactly **2 types × 4 creature
names, all level 1**:

- **Beasts, level 1** (`BESTIARY.Beasts[0]`, `content/bestiary.js:14-16`):
  `Bat/Rat`, `Shriek`, `Viper` — all three level-1 Beasts entries are
  exercised (there are only three in that tier).
- **Humans, level 1** (`BESTIARY.Humans[0]`, `content/bestiary.js:50`):
  `Dante` — the only level-1 Humans entry (there is only one in that tier, so
  it is unconditionally exposed by any Humans-forced fixture). Seed 303
  (`parley`) rolls Dante twice — that's two rolled instances of the SAME
  bestiary entry, not two distinct creatures.

**Why only level 1:** every fixture starts a level-1 character on floor 1.
`startCombat`'s level math (`engine/combat.js:98-135`) is:

```
maxLvl = clamp(min(c.level, state.floor.depth), 1, 5)
lvl    = clamp(maxLvl - (rng.d(4) === 1 ? 1 : 0), 1, 5)
roster = BESTIARY[type][lvl - 1]
picked = rng.pick(roster)
```

With `c.level === 1` and `depth === 1`, `maxLvl` is always `1`, and the `d4`
downgrade roll clamps at the floor of `1` — there is no way to reach `lvl`
2 from that starting point. The boundary is exact: a level-2 hero on depth 1
still gives `min(2,1)=1`; depth 2 with a level-1 hero still gives
`min(1,2)=1`. Only `level >= 2 AND depth >= 2` could ever expose a level-2
bestiary entry, and no fixture reaches that combination.

**Why only Beasts and Humans:** the combat/magic fixtures explicitly force
those two types via their `startCombat` action's `forced` field (see the
table above — every fight row's "Forced type" is `Beasts` or `Humans`, never
any other `ENC_TYPES` value). The magic `heal`/`potion`/`scroll` scenarios
never call `startCombat` at all, so they roll nothing. The encounters
domain's `springTrap`/`openChest`/`encounterDot` never reference `BESTIARY`
at all (`content/encounters.js` has zero matches for `"BESTIARY"`). The
economy domain's `openStore`/`buyItem`/`leaveStore` never touch combat
either. The movement fixture's seed 256 was deliberately chosen (see the
fixture's own `_note`) so its 8-hour wandering-monster check draws zero 1s on
d20 across all 101 actions — this replay CONFIRMS that by executing the
actual check (`trigger: "none"`, not `"wandering"`), not by trusting the
fixture's comment alone.

## What this means for Phase 18 (constraints)

(a) Any change to `wp`, `sp.dmg`, `sp.atk`, `sp.toHit`, `sp.ar`, `sp.noArmor`,
`sp.twice`, `sz`, `i`, or `n` of `Bat/Rat`, `Shriek`, `Viper`, or `Dante`
changes parity output and requires a narrow, named `combatComparable`
carve-out (FID-05 / BEST-03) modelled on `stripFoeDamageClosures`
(`test/parity/harness/comparables.js:158`) with a stated rationale — never a
fixture regeneration.

(b) Every other creature — every level 2-5 entry of every type, and every
Demons / Lair Beasts / Magical / Walking Dead entry at any level — is
unconstrained by the parity suite and can be rebalanced freely.

(c) The LENGTH and ORDER of `BESTIARY.Beasts[0]` and `BESTIARY.Humans[0]` are
load-bearing, because `startCombat` picks with `rng.pick(roster)` (index =
`floor(next * length)`). Inserting, removing, or reordering a level-1
Beasts/Humans entry changes which creature every combat/magic seed rolls and
would break every combat fixture.

(d) Phase 19's ability kits (Djinni, Krupke, Drudge, Vampire, Stalka Beast)
touch none of the four exposed creatures.
