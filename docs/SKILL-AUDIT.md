**Phase:** 90-spell-skill-audit (plan 90-01)
**Date:** 2026-09-30
**Status:** closed. The audit was written and its two balance calls (Q10 and Q11) ruled by the user on 2026-09-30; plans 90-02 to 90-11 built the fixes and plan 90-12 closed the table.
**Closed:** 2026-10-01 (plan 90-12): every row reads its shipped text, a final verdict and its Hero and Joiner cells, and every pin below names a test file and a test title that exist (63 distinct pins). `test/unit/skill-audit.test.js` fails on any row still reading `fix engine`, `fix text` or `balance call`, on a pin whose file or title is missing, on a skill or ability with no row, and on a row whose Text cell is not the live `txt`; `test/unit/spell-skill-text-engine.test.js` fails the day a skill's text and the numbers the engine uses drift apart.

Every Fighter skill, every Thief skill, every pool ability and the Bard's Sing has one row: what its text promises, what the engine does, its cooldown or once-per-fight rule, whether it auto-hits or forces a critical, its bonus terms, who can use it (the hero, and a Joiner), what canon says, a verdict and the tests that pin it. A mismatch is never waved through: it is fixed by a named plan, or it is a recorded ruling. The spell twin of this table is `docs/SPELL-AUDIT.md`.

## How to read this table

**Text** is what the player reads: the `txt` (and `txt2`) in `content/skills.js` and `content/abilities.js`, the Hero tab's special-skills list and ability rows (`src/browser/heroTab.js#abilitiesViewFor`: the txt plus its state "ready", "cd N rounds" or "once a fight"), and the combat menu's ABILITIES row (`src/browser/combatMenu.js#abilityRows`: READY, READY · ONCE PER FIGHT, ONCE PER FIGHT · SPENT or N ROUNDS, and the txt as its description).

**Engine** names the file and function that runs the skill and what it does in numbers.

**Rule** states the cooldown (rounds) or "once per fight" (`cd: "fight"`, cleared by `endCombat`), whether the strike auto-hits or forces a critical, the to-hit shift in roll-high form ("+3 to hit", "−2 to hit"), the damage bonus, the targets and the minimum foe count.

**Hero** names the engine site that runs it for the hero (the `useAbility` case, or the passive read). **Joiner** names the engine site for a Joiner (`engine/combat.js#resolveMemberAbility`'s case and the `pickMemberAbility` tag) or says "cannot" and why (a passive no Joiner code ever reads). "Who can use it: a Joiner uses a skill the way its text describes" is the standing rule (90-CONTEXT).

**Joiner use policy** (`engine/combat.js#pickMemberAbility`, no rng): in round 1 the first ready ability tagged opener; else against a foe above half hp the first ready ability tagged damage (Last Stand only at or below a quarter of its hp); else, below half its own hp, the first ready ability tagged defensive; else a plain strike (or a spell, for a Magic User). A Joiner uses only abilities of its own class that its sheet owns.

**Canon** cites the rulebook (`mazeworld.pdf`, printed page) and the frozen prototype (`test/parity/prototype-master.js.txt`, line, read only). The user's rulings override both, and the Canon cell names the ruling when it does. Most abilities are Phase 38 additions with no rulebook entry.

**Default fix direction:** the engine does what the text promises, unless the text is a typo or the user ruled otherwise. A wording-only fix is the text's; a fix that moves balance materially is a balance call and goes to the user before it is built.

**Verdict vocabulary** (the closed vocabulary `test/unit/skill-audit.test.js` accepts; no open verdict is left): `match`; `fixed engine (90-NN)` and `fixed text (90-NN)` (plan 90-NN built the fix and a test pins it); `ruled (Qn, 2026-09-30) -> 90-NN` and `ruled (2026-09-30) -> 90-NN` (a user ruling settles the row and the plan 90-NN named built it; Death Touch is the one such row); `Phase 91 (IDENT-NN)` and `Phase 92` for rows handed on (Sing is the one such row). `Pinned by` is a list of `test/unit/<file>.test.js: <test title>` separated by `; `; every row is pinned by the text-vs-engine guard (every number the text states is claimed by one fact and equals the engine), every fixed or ruled row names the test that would fail if the fix were reverted, and only the Phase 91 hand-off reads `—`. The test reads each named file and each title, so a pin cannot name a test that is gone or renamed.

**Plan owners:** 90-02 Pommel Strike, hero and Joiner (ABIL-07); 90-04 the depth-rising resist, which also lets a blinded foe's top-face hit stop being a critical (Blind and Dirty Trick share the flag); 90-10 every other audit engine fix (Joiner skill use included); 90-11 TEXT-01 wording for every skill row (faces become "+N to hit" or "foes −N to hit you" with the d20 range named), built: `fixed text (90-11)` rows are pinned by `test/unit/spell-skill-text-wording.test.js`; 90-12 the text-vs-engine guard and the audit close.

**Two facts the rows lean on.** A duration ability with a cooldown runs its effect first and then its cooldown (`engine/effects.js#startEffect`), and the foe turn of the use round ticks the fresh timer once, so "for two rounds" covers the use round and two more (`abilities.js#abilityEffectTicks`). And an ability's cooldown starts when it is used: `cd: "fight"` means spent until the fight ends.

A table skill whose `active` marker names a catalog ability is one row (its catalog entry is the same line), never two. `test/unit/skill-audit.test.js` pins that order and fails on a missing, duplicate or unknown row.
